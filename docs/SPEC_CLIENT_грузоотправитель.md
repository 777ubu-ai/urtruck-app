# UrTruck — Спецификация роли «Грузоотправитель» (client)

> Документ для команды разработки. Описывает полную логику клиентской (грузо­владельческой)
> стороны маркетплейса UrTruck: экраны, кнопки, переходы, состояния, API, бизнес-правила.
> Источник истины — фактический код (`src/`, `backend/api/marketplace.py`). Версия: 2026-07.

---

## 0. Что такое UrTruck и роль «client»

UrTruck — FTL-маркетплейс грузоперевозок по коридору **Китай ↔ СНГ** (Казахстан, Китай,
Узбекистан, Россия, Кыргызстан). Модель — **биржа ставок** (как InDrive, но для фур):
**грузоотправитель публикует груз → перевозчики делают ставки → грузоотправитель выбирает**.

Две роли:
- **`driver`** (водитель/перевозчик) — ищет грузы, делает ставки, везёт.
- **`client`** (грузоотправитель/грузовладелец) — **предмет этого документа**: публикует груз,
  получает предложения, выбирает перевозчика, ведёт сделку.

Акцентный цвет клиента — **`#F59E0B`** (янтарный). Фон `#0C0A09`, карточка `#1C1917`.

## 1. Навигация клиента (таб-бар)

Клиентский таб-бар (`AppNavigator.js`, `isDriver === false`) — 5 позиций, центральная «+»:

| Вкладка | Экран | Назначение |
|---|---|---|
| **Мои грузы** | `MyTripsScreen` (`MyWork`) | опубликованные грузы + входящие **Предложения** + сделки |
| **Грузы / Лента** | `FeedScreen` (`Feed`) | лента (просмотр рынка), поиск, фильтры |
| **➕ Создать** | `PublishStub` → `CreateCargoScreen` | публикация нового груза (янтарная приподнятая кнопка) |
| **Чаты** | `ChatsListScreen` (`Chats`) | список чатов по сделкам/ставкам, бейдж непрочитанного |
| **Профиль** | `ProfileScreen` (`Profile`) | профиль, Кошелёк, Настройки, Помощь, выход |

**Канон:** клиентский таб-бар нельзя менять без отдельного согласования. «Создать» — это
центральная кнопка, а не обычная вкладка.

Навигация реактивна (по `AuthContext`): без токена — онбординг/вход; гость (`hasToken && !session`)
— лента + просмотр, но без публикации; после входа с ролью `client` — полный стек.

## 2. Жизненный цикл груза (главный сценарий)

```
[Создать груз] → active
      │  (перевозчики шлют ставки)
      ▼
[Предложения: N ставок]  ── принять ──▶ создаётся СДЕЛКА (deal), груз закрывается
      │  (или: отклонить / контр-оффер / чат)
      ▼
[Сделка in_progress] → статусы: погрузка · граница · выгрузка → delivered
      │
      ▼
[Взаимные отзывы] (двусторонний рейтинг)
```

### Статусы (из `backend/api/marketplace.py`)
- **Груз (cargo):** `active` (опубликован) → `cancelled` (снят) / закрывается при принятии ставки.
- **Ставка (bid):** `pending` → `countered` (клиент выставил встречную) → `accepted` / `rejected` / `cancelled`.
- **Сделка (deal):** `in_progress` → промежуточные статусы (погрузка/граница/выгрузка) → `delivered`.

## 3. Экраны и логика — по шагам

### 3.1. Создание груза — `CreateCargoScreen`
Поля формы (`useState`):
- **Маршрут:** `from` / `to` — структурированные точки через `RoutePointPicker` (страна+город/пункт).
- **Тип кузова** (`truckType`): `tent` (тент) · `ref` (рефрижератор) · `platform` (площадка) ·
  `auto` (автовоз) · `izoterm` (изотерм) + свободное «другое».
- **Описание груза** (`cargoDesc`).
- **Дата выезда** (`pickupDate`).
- **Вес (т)** и **Объём (м³)**.
- **Цена:** режим «фиксированная» или «по договорённости» + **валюта** (USD/KZT/RUB/CNY;
  символы через `formatPrice`, ₸/$/₽/¥).
- **Фото груза** (опц.).

Кнопка «Опубликовать» → `marketAPI.createCargo(data)` → `POST /api/v1/market/cargos` → груз `active`.
Валидация: маршрут (откуда/куда) обязателен; дата выезда не в прошлом (бэкенд `400`).

### 3.2. Лента / поиск — `FeedScreen`
- `marketAPI.listCargos({status, fromCity, toCity, cargoType, limit, offset})` → `GET /cargos`.
- Фильтры: **Направление · Дата · Кузов · Цена** (чипы-фильтры сверху).
- Тап по карточке → **`CargoDetail`**.
- Суммы — через `formatPrice(amount, currency)` (валюта груза, не хардкод `$`).

### 3.3. Мои грузы + Предложения — `MyTripsScreen`
Источник данных: `marketAPI.myDashboard()` → `{ my_trips, my_cargos, my_bids, incoming_bids, my_deals }`.

Сегменты (вкладки внутри экрана):
- **Мои грузы** — опубликованные `my_cargos` (со счётчиком «💬 N предложений ›» на карточке).
- **Предложения (N)** — входящие ставки `incoming_bids` от перевозчиков.
- **В работе / Архив** — сделки `my_deals`, завершённые/отменённые.

По каждой входящей ставке — кнопки (у всех стабильные `testID`):
| Кнопка | Действие | API |
|---|---|---|
| **Принять** (`bid-accept`) | принять ставку → создаётся сделка, остальные ставки авто-`rejected` | `POST /bids/{id}/accept` |
| **Отклонить** (`bid-reject`) | отклонить ставку | `POST /bids/{id}/reject` |
| **Контр** (`bid-counter`) | встречная цена (модалка `BidModal`) → ставка `countered` | `POST /bids/{id}/counter` |
| **Чат** (`bid-chat`) | открыть комнату переговоров по ставке | `openBidChat` → `POST .../chat` |
| **Принять контр** (`bid-accept-counter`) | если перевозчик согласился на встречную | `POST /bids/{id}/counter/accept` |

Тосты: «Предложение принято» / «Предложение отклонено». Терминология везде — **«предложение»**;
но сумма сделки называется **«Ставка: <сумма> <валюта>»**.

### 3.4. Карточка груза — `CargoDetail`
- `marketAPI.getCargo(id)` + `listBids({cargoId})` — детали + список ставок.
- Владелец груза видит: список предложений с теми же действиями (принять/отклонить/контр/чат).
- Кнопки: **Редактировать** (`updateCargo` → `PATCH /cargos/{id}`), **Снять с публикации**
  (`deleteCargo` → `DELETE /cargos/{id}`).
- ⚠️ Модалка ставки `BidModal` currency-aware (валюта груза).

### 3.5. Сделка — `DealRoom` / `ChatScreen`
После принятия ставки создаётся **deal**:
- `marketAPI.getDeal(dealId)` → детали (стороны, сумма «Ставка: … <валюта>», статус).
- **Чат сделки** — переписка клиент↔водитель (с авто-переводом, канал `/api/v1/chat`).
- **Статусы перевозки:** `updateDealStatus(dealId, newStatus)` → `POST /deals/{id}/status` —
  погрузка → граница → выгрузка → `delivered`.
- **Трекинг:** `sendDealLocation` / `getDealLocation` (`/deals/{id}/location`) — где груз сейчас.

### 3.6. Чаты — `ChatsListScreen`
Список активных чатов (по ставкам/сделкам). Бейдж непрочитанного, суммы с валютой (`bid_currency`).

### 3.7. Профиль — `ProfileScreen`
Имя, город, аватар; Кошелёк (`WalletScreen`, транзакции/FX, монетизация под флагом `IS_BETA`),
Настройки, язык (RU/KK/ZH/EN), Помощь, Выход, Удалить аккаунт.

## 4. Полный список API (клиентские, `BASE = /api/v1/market`)

**Грузы:** `POST /cargos` (создать) · `GET /cargos` (лента) · `GET /cargos/{id}` ·
`PATCH /cargos/{id}` (редактировать) · `DELETE /cargos/{id}` (снять).
**Ставки (входящие):** `GET /bids?cargoId=` · `POST /bids/{id}/accept` · `POST /bids/{id}/reject` ·
`POST /bids/{id}/counter` · `POST /bids/{id}/counter/accept` · `POST /bids/{id}/counter/decline`.
**Дашборд:** `GET .../dashboard` → `{my_cargos, incoming_bids, my_deals, …}`.
**Сделки:** `GET /deals/{id}` · `POST /deals/{id}/status?new_status=` · `POST|GET /deals/{id}/location`.
**Чат:** `/api/v1/chat/...` (комнаты, сообщения, перевод).

Авторизация: заголовок `Authorization: Bearer <token>` (регистрационный токен из `storage`,
ключ `ur_reg_token`).

## 5. Бизнес-правила и краевые случаи (важно для разработки)

1. **Один активный груз = одна сделка.** При принятии ставки груз закрывается, остальные
   `pending/countered` ставки авто-`rejected` (backend транзакционно).
2. **Нельзя дважды поставить на занятый груз** → `409`. Ставка `amount=0` → `400`.
3. **Валюта:** суммы всегда через `formatPrice(amount, currency)` — символ по валюте груза,
   фолбэк USD. НЕ хардкодить `$`.
4. **Гостевой режим:** без сессии клиент видит ленту и карточки, но публикация/ставки требуют входа
   (deferred auth — открывается вход).
5. **Верификация:** защищённые действия проходят через `VerificationGate`.
6. **Пустые состояния:** `EmptyState` на «нет грузов / нет предложений / нет чатов».
7. **Терминология:** входящие = «предложения»; цена сделки = «Ставка».
8. **Локализация:** все тексты через `t(...)`, 4 языка (RU/KK/ZH/EN).

## 6. Стек (для контекста)

- **Backend:** Python 3.12 + FastAPI + SQLite (+ Redis, APScheduler). Роутеры под `/api/v1/...`.
  Маркетплейс — `backend/api/marketplace.py`.
- **Frontend:** React Native + Expo SDK 52 (JS), собирается в web/PWA и Expo Go/EAS.
- **Данные:** `src/utils/marketAPI.js` (REST-клиент), `AuthContext` (сессия/роль), `store.js`
  (демо/pub-sub), `ThemeContext`, `i18n`.
- **Прод:** сервер `185.22.65.11`, сайт `urtruck.kz` (nginx: `/` → фронт, `/security/*` → бэк:8001).
