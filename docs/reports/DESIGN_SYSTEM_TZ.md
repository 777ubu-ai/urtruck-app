# UrTruck — Design System ТЗ (Phase 1)

**Дата:** 2026-05-12
**Версия:** v2.0 (re-design)
**Контекст:** TestFlight build 1.0.0 (9) уже в TestFlight, функционально работает. Текущий визуальный стиль — «детский» с эмодзи-иконками, не соответствует серьёзному B2B-логистическому продукту.

---

## Стратегия

> «Делаем не копию inDrive и не оставляем текущий "весёлый" стиль.
> UrTruck = строгий, светлый, международный, логистический интерфейс с оранжевым акцентом.»

Главная ошибка текущего UI: визуально приложение выглядит игрушечно. Для логистики, где люди везут груз на тысячи долларов, это слабый сигнал доверия.

```
Грузы · Рейсы · Транспорт · Чаты · Профиль
```

**Не смешивать одной навигацией.** Driver и shipper — разные роли с разными задачами.

## 4. Экраны по приоритету

### Приоритет 1 — Главный экран

**Что починить:**
- Убрать «— → —» (✅ уже Stage 50/52)
- Карточка показывает: маршрут, тип кузова, вес, объём, дату, цену
- «0 отзывов» не показывать когда отзывов нет (✅ уже)
- Кнопка «Подробнее» — outline, не кричащая

**Эталон карточки:**
```
Хоргос → Алматы
Тент · 20 т · 110 м³
Дата подачи: 17 мая
Цена: $2 500
Подробнее
```

### Приоритет 2 — Разместить груз

**Структура блоков:**
1. **Маршрут** (откуда / куда)
2. **Груз** (описание / вес / объём / упаковка)
3. **Транспорт** (тип кузова / темп. режим / ADR / загрузка)
4. **Дата** (загрузка / выгрузка)
5. **Оплата** (по договорённости / указать цену + валюта + форма)
6. **Дополнительно** (фото / комментарий / документы)
7. **Публикация**

### Приоритет 3 — Мои грузы

**Структура:**
- Вкладки: Активные / В работе / Архив
- Слово «Ставки» → **«Предложения»** (звучит профессиональнее)
- Статус-цвета:
  - Активен — `#22C55E`
  - В работе — `#F59E0B`
  - На проверке — `#F59E0B`
  - **Отменён — `#94A3B8` (серый, НЕ зелёный)**
  - Завершён — `#22C55E`
  - Черновик — `#CBD5E1`

### Приоритет 4 — Чаты

**Запрещено в UI:**
- `guest_5af3...`
- `d3`, `d4`
- `agent-boris`
- `Bid Serik [ar-...]`

Все технические имена → переводимый fallback **«Собеседник»** (`chat_partner_fallback`).

**Структура:**
- Поддержка UrTruck (топ карточка, online dot)
- Диалоги:
  - Имя / компания
  - Привязка к рейсу: «По рейсу Хоргос → Алматы»
  - Последнее сообщение
  - Время
  - Индикатор непрочитанных

### Приоритет 5 — Профиль

**Текущие пункты:**
- Имя, телефон, роль, город, статус проверки

**Нужно добавить:**
- **Документы** (для международных грузов критично)
- **Финансы**
- **Безопасность**
- **Компания / Реквизиты**
- **Отзывы** (если есть)

**Статус проверки:**
- Не просто «На проверке»
- А «Профиль на проверке. Обычно занимает до 24 часов»
- Если не хватает документов: «Нужно добавить документы — завершите профиль для большего числа откликов»

## 5. Что НЕ делаем

- ❌ Лайм / зелёный как у inDrive — это копия. UrTruck = оранжевый (логистика, энергия, предупреждение).
- ❌ Просто «красить» экраны без системы — ловушка.
- ❌ Менять всё разом по 36 экранам — лучше 5 эталонных, потом масштабировать.
- ❌ Эмодзи в иконках («детский» вид).

## 6. Прямое ТЗ дизайнеру

> Нужно переработать визуальный стиль UrTruck в более строгий B2B-логистический интерфейс.
>
> 1. Убрать emoji-иконки, заменить на единый Feather outline icon set.
> 2. Использовать светло-серый фон `#F4F6FA`, белые карточки, тёмно-синий основной текст `#0F172A`, серый вторичный `#64748B`.
> 3. Оранжевый `#F59E0B` использовать только для CTA, активных состояний и важных акцентов.
> 4. Привести нижнюю навигацию к единому стилю с возможностью role-aware варианта.
> 5. Переделать карточки грузов: маршрут, кузов, вес, объём, дата, цена, статус, число предложений.
> 6. Исправить статусы: «Отменён» — НЕ зелёный.
> 7. В чатах убрать технические имена `guest`/`d3`/`d4`, показывать имя или «Собеседник».
> 8. В профиле добавить «Документы», «Финансы», «Безопасность».
> 9. Все 5 эталонных экранов должны выглядеть как единая система.
>
> Передать в Figma → потом разработка переносит в React Native.
