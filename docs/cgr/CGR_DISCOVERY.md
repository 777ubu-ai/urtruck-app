## 🔑 ГЛАВНОЕ ОТКРЫТИЕ: у CGR есть официальный REST API (Swagger)

`https://cgr-api.qoldau.kz/swagger/index.html` → `swagger/v1/swagger.json`
**title:** `CARGORUQSAT API`, **version:** `v1`. Всего **5 методов:**

| Метод | Назначение | Auth |
|---|---|---|
| `GET /Checkpoint/Auth` | Bearer-токен **точки** (поста). Параметр `RegistrationToken` (query, required) — «виден в просмотре пункта пропуска». Выдаётся один раз, клиент хранит локально. | — |
| `GET /Checkpoint/TruckNumbers` | Массив ГРНЗ из очереди на день запроса (`TruckPlatesResponse`). | Bearer точки |
| `POST /Checkpoint/CamEvent` | Приём события фиксации камерой (ANPR, `plateImage` — текст с камеры). | Bearer точки |
| `GET /WaitingArea/Auth` | Bearer-токен точки **зоны ожидания**. | — |
| `POST /WaitingArea/CamEvent` | Событие камеры в зоне ожидания. | Bearer точки |

**Вывод:** этот API — **операторский** (для камер/АРМ на физических постах и в
зонах ожидания). `RegistrationToken` есть только у оператора конкретной точки —
для приложения-агрегатора недоступен «из коробки». Это, вероятно, и есть scope
договора Smart Bridge **ORGAM-S-9317 / CargoRuqsatAppsServiceSync** — но
**driver-facing read (статус брони/позиция)** этим публичным Swagger НЕ
покрывается. → нужно техприложение к договору, чтобы понять, даёт ли он
партнёрский доступ. **Ссылки со страницы cgr-api:** соглашение
`qoldau.kz/files/cargo/agreement.pdf`, формат события `camevent_info.docx`,
модератор-портал `cgr-moderator.qoldau.kz`.

**Для нашей задачи (показать водителю очередь) операторский API не требуется —**
всё нужное есть на публичных SSR-страницах ниже.

### 1.1. Загруженность постов + справочник КПП (замена scoreboard)

- **`/ru/start?id=stat`** — блок «Загруженность постов», **32 КПП**, метка
  «**Актуально на: 13.06.2026 17:23**», агрегированная статистика (SSR).
  UI-пакет `square-stat` (сетка статусов). Числовые значения рендерятся в HTML
  (SSR), парсятся из разметки.
- **`/ru/registry/checkpoint/list`** — официальный справочник переходов
  **парами** (KZ-сторона — соседняя сторона): напр. «Достык - Алашанькоу»,
  «Бахты - Покиту». Это seed для `border_checkpoints` вместо хардкода `BORDERS`.
- **Рендеринг:** SSR (данные в HTML, не голый JS-shell) → парсер на bs4/lxml.
- Мультиязычность: префиксы `/ru /kz /en /cn /uz /tk /fa` — есть имена на разных
  языках (берём ru/kz/cn/en для `name_*`).

### 1.2. Реестр бронирований `/ru/registry/public-list`

- **Формат:** SSR HTML-таблица. **Всего записей: 18 578.** Пагинация `?p=N`
  (до `?p=1239`). Фильтры на форме: пункт пропуска, статус (`flStatus`,
  multiselect), диапазон дат.
- **Колонки (4):** `Пункт пропуска` · `ГРНЗ` · `Дата/время очереди` · `Статус`.
- **ПДн:** ИИН и ФИО **НЕ публикуются** (только ГРНЗ). 🟢 Это снимает основной
  privacy-риск: длину очереди считаем агрегатом по статусу, чужие номера не
  показываем.
- **Статусы:** `В очереди`, `Опаздывает`, `Пересёк пункт пропуска`,
  `Пропуск отозван`; в фильтре также `производится оплата` (WaitingPayment),
  `проверка провалена`, `вызван на пункт пропуска`, `пропуск аннулирован`.
- **Поиск по ГРНЗ:** через фильтр формы (можно отдавать водителю его статус по
  его номеру, не трогая чужие ПДн).

### 1.5. robots.txt и ToS
- `robots.txt` → **302-редирект** (отдельного файла фактически нет) → явного
  `Disallow` на `/ru/registry/*` не обнаружено. Реестры спроектированы как
  публичные для просмотра.
- ToS/политика: `https://qoldau.kz/ru/Politic`. **Вердикт: 🟡 серая зона** —
  технического запрета не видно, но юридическую формулировку про
  автоматический доступ/редистрибуцию должен подтвердить Толя (advisor) перед
  продом. UA честный, частота низкая, ПДн третьих лиц не показываем.

### 1.6. Rate limit
- Стресс-тест **не проводил** (чтобы не нагружать CGR без нужды). Оставляем
  консервативно `CGR_RATE_LIMIT_REQUESTS_PER_MIN=20` и кэш в БД (scoreboard раз
  в 5 мин). При реализации — снять порог 429 с прод-VPS (KZ IP).
