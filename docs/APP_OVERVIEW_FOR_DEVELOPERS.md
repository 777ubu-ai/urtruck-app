# UrTruck — полное описание приложения для команды разработки

Документ для программистов: что это за продукт, как он устроен, полная логика
работы обеих ролей (грузоотправитель и водитель), архитектура, бизнес-правила,
API и данные. Актуально на 18.07.2026.

---

## 1. Суть продукта

**UrTruck** — FTL-маркетплейс грузоперевозок для коридора **Китай ↔ СНГ**
(Казахстан, Россия, Узбекистан, Кыргызстан, Таджикистан). Аналогия — «inDrive
для фур»: грузоотправитель публикует груз со своей ценой, водители-дальнобойщики
предлагают свои ставки, стороны договариваются напрямую, без диспетчеров и
посредников. Платформа даёт доверие (верификация водителей, рейтинг, отзывы,
чёрный список) и инструменты сделки (чат, документы, трекинг машины,
электронная очередь на границе).

**Монетизация:** сейчас бета — всё бесплатно (флаг `IS_BETA = true` в
`src/config/supabase.js`; не выключать без согласования). Комиссия 0%.

**Языки:** RU / KK (казахский) / ZH (китайский упрощённый) / EN — полная
симметрия (~1740 ключей на язык, `src/utils/i18n.js`). Названия городов
дополнительно локализуются словарём (`src/utils/places.js`): «Хоргос» → 霍尔果斯.

## 2. Технологический стек

| Слой | Технологии |
|---|---|
| **Мобильное приложение** | React Native + Expo SDK 52 (JavaScript). Один код на iOS / Android / Web(PWA) |
| **Web/PWA** | Тот же код, собирается `npm run build:web`, живёт на **urtruck.kz** |
| **Backend** | FastAPI (Python 3.12) + SQLite + Redis + APScheduler. Сервер 185.22.65.11, PM2-процесс `urtruck-security-api`, порт 8001. API-префикс `/api/v1/...` (в проде через nginx `/security/api/v1/...`) |
| **Хранение файлов** | Storage-абстракция: local FS / Supabase Storage / S3 (`STORAGE_PROVIDER`). Файлы отдаются только по подписанным URL |
| **Push** | Native — Expo Push/APNs (`push_tokens_native`); Web — VAPID Service Worker (`push_subscriptions`) |
| **Auth** | OTP по телефону (WhatsApp/Telegram-бот; в mock-режиме код в логах). Токен `ur_reg_token` → `Authorization: Bearer`. Supabase — только для OTP клиентов |
| **Перевод** | OpenAI (переводчик чата) |
| **CI/CD** | Push в `main` на GitHub → GitHub Actions собирает web + заливает backend + рестарт PM2. iOS — EAS Build → TestFlight |

**Тёмная тема — основная** (по умолчанию), есть светлая. Цвета ролей:
водитель — изумрудный неон `#00E676` (текст на кнопках тёмный, контраст AAA),
грузоотправитель — мандарин `#FF8400` (обновлено 18.07, текст тёмный).

## 3. Роли и навигация

Роль выбирается после OTP-входа и определяет весь интерфейс.

### Водитель (driver) — таб-бар 5 вкладок (канон, не менять):
`Грузы (Feed)` · `Рейсы (MyWork)` · `Очередь (Queue)` · `Чаты` · `Профиль`

### Грузоотправитель (client) — таб-бар 5 вкладок:
`Грузы (мои)` · `Машины (лента рейсов)` · `＋ Разместить` · `Чаты` · `Профиль`

Навигация реактивная (`src/navigation/AppNavigator.js`): нет токена → онбординг
(3 слайда → телефон → OTP → роль → профиль); есть токен без роли → выбор роли;
полный вход → главные табы + детальные экраны.

## 4. Полный жизненный цикл сделки (ядро логики)

### Шаг 1. Публикация
- **Клиент создаёт ГРУЗ**: откуда/куда (полноэкранный пикер городов: поиск,
  недавние, избранное, популярные, погранпереходы, геолокация) → описание →
  тип кузова (tent/ref/platform/auto/izoterm + своё) → **дата загрузки
  (обязательна)** → вес/объём → **цена (обязательна, «по договорённости»
  удалена)** + валюта (KZT/USD/RUB/CNY, автоподбор по стране отправления) →
  тип оплаты (нал/безнал/любая) → фото груза (опц.).
- **Водитель создаёт РЕЙС** (свободную машину): маршрут, дата выезда
  (обязательна), тип кузова, тоннаж/объём, **цена (обязательна)**.

### Шаг 2. Жизнь публикации — «Модель А» (сроки)
- Публикация живёт **3 дня** (день выезда + 2), потом уходит из общей ленты.
- Напоминания владельцу: +1 день «Ещё актуально?», +2 «Завтра уберём»,
  +3 «Убрано — вернуть?». Дальше не спамим.
- Продление **одним тапом** «✅ Ещё актуально» (дата = сегодня, снова в ленте)
  или «📅 Изменить дату». Endpoint: `POST /market/cargos/{id}/extend`,
  `/market/trips/{id}/extend`.
- Просроченное у владельца остаётся в «Архиве» с пометкой «⏳ Срок истёк».

### Шаг 3. Торг (ставки)
- Водитель видит груз в ленте → «Предложить цену» → ставка (bid) со своей
  суммой. Клиент видит все ставки на своём грузе.
- Клиент может: **Принять** / **Отклонить** / **Контр-оффер** (своя сумма) /
  открыть чат. Водитель может изменить/отменить ставку, принять/отклонить
  контр-оффер. Гонки закрыты на бэке (conditional UPDATE, дедуп ставок).
- Зеркально: клиент может ставить предложение на рейс водителя.

### Шаг 4. Сделка (deal)
Принятие ставки создаёт **deal** + автоматически **чат-комнату сделки**.
Статусы сделки и таймлайн (виден обеим сторонам):

`🤝 Принят (accepted)` → `🚛 В пути (in_progress)` → `🛂 На границе (at_border)`
→ `✅ Доставлен (delivered)` (или `❌ cancelled` — до выезда).

- Кнопки по шагам у **водителя**: «Выехал» → «На границе» → «Доставлено».
- **Клиент** подтверждает доставку. Каждая смена статуса = push + запись в
  колокольчик + событие в immutable-timeline сделки.
- `delivered` автоматически помечает груз `completed`; `cancelled` возвращает
  груз в `active`.

### Шаг 5. Трекинг «Где машина»
- Водитель **автоматически** транслирует геопозицию по активным сделкам
  (раз в 25с, пока приложение открыто, после разового разрешения на локацию;
  хук на уровне всего приложения — ничего нажимать не надо).
- Клиент открывает «📍 Где машина»: карта + **осталось км / скорость /
  ETA / «на границе» / обновлено N мин назад** (поллинг 10с).
- Endpoints: `POST/GET /market/deals/{id}/location` (только участники;
  работает на статусах accepted/in_progress/at_border/picked_up).
- Фоновый GPS (при закрытом приложении) — НЕ реализован (следующая фаза).

### Шаг 6. Чат сделки (подробно — docs/CHAT_PUSH_SPEC.md)
- Комната **на каждый груз отдельная** (ключ `c:{cargo_id}:{p1}:{p2}`) —
  переписки по разным грузам не смешиваются.
- Текст (идемпотентно, офлайн-очередь), фото (камера/галерея), голосовые
  (upload аудио на сервер), документы сделки (PDF/фото со статусами загрузки),
  автоперевод (по кнопке и всей ленты), быстрые фразы **по роли и по этапу
  сделки**, «печатает…», галочки ✓/✓✓, шапка с грузом и маршрутом,
  кнопка 📞 (реальный номер контрагента — только участнику сделки).
- Вся переписка — в SQLite на сервере (`chat_messages`/`chat_rooms`).

### Шаг 7. Завершение
- После `delivered` → обе стороны оставляют **отзыв** (двусторонние отзывы,
  рейтинг 0–5, теги). Рейтинг влияет на скоринг водителя.

## 5. Верификация и доверие (водитель)

PRO-флоу (5 шагов): удостоверение (ИИН) → селфи (liveness) → документы на
авто → фото фуры снаружи → параметры фуры → на модерацию.
- OCR документов (Tesseract rus+eng+kaz+uzb+chi_sim), face match
  (эвристика/поэтапно dlib), проверка по чёрным спискам (Della/ATI/Telegram
  парсеры), гос-чекеры КЗ/РФ/УЗ/КГ/ТЖ (пока mock).
- **Скоринг 0–100** из 6 компонентов (backend `scoring/`), уровни
  верификации 0–3. Level-гейты на API (`require_level(1)` на чат/ставки).
- Статусы водителя: unverified → pending/manual_review → approved / rejected.
- «Надёжность» и бейдж «Верифицирован» видны клиенту в профиле водителя.
- Просмотр ленты и очереди на границе — доступен ДО верификации (гость),
  действия (ставка/чат/публикация) — только после.

## 6. Электронная очередь на границе (CGR / CarGoRuqsat)

Уникальная фича для коридора Китай↔КЗ. Интеграция с гос-системой CGR
(cgr.qoldau.kz), официальное письмо от АО «ИУЦ» есть.
- **Табло очередей** по погранпереходам (Нур Жолы, Достык, Калжат…) —
  публично, живые данные (число машин, статусы).
- **Проверка по госномеру**: водитель вводит ГРНЗ → видит свой статус
  в очереди (в очереди / вызван / пересёк / отозван).
- **Слежение + пуш**: «🚛 Ваша очередь подошла» (watch по ГРНЗ, джоба каждые
  10 мин). Экран «Мои номера в очереди».
- Полная интеграция (бронирование) — Трек 2 через Smart Bridge, ждёт
  договора (см. docs/SMART_BRIDGE_CGR_INTEGRATION_REQUIREMENTS.md).

## 7. Push-уведомления (события)

| Событие | Кому |
|---|---|
| Новое сообщение чата | собеседнику (suppress, если комната открыта — native) |
| Ставка принята / отклонена / контр-оффер / скидка | второй стороне (суммы в реальной валюте) |
| Смена статуса сделки (В пути / На границе / Доставлен / Отменено) | второй стороне |
| Очередь на границе подошла / пропуск отозван | водителю (watch по ГРНЗ) |
| Срок публикации истекает/истёк (+1/+2/+3 день) | владельцу |
| Новые грузы по сохранённому маршруту; неактивность 3 дня | пользователю |

Всё дублируется в **колокольчик** (in-app уведомления) + deep-link на нужный
экран. Дедуп через `push_log`. Бейдж непрочитанного на иконке приложения.

## 10. Бизнес-правила (запомнить)

1. **Цена всегда обязательна** (груз и рейс). «По договорённости» удалена,
   включая обход через редактирование.
2. **Дата обязательна**; публикация живёт 3 дня; продление одним тапом.
3. **Чат = заказ**, не человек. Один водитель + один клиент по двум грузам =
   два чата.
4. **Статусы сделки** только: accepted → in_progress → at_border → delivered
   / cancelled. Любая смена = push + колокольчик + timeline.
5. **Демо/seed-данные в проде запрещены.**
6. Все пользовательские тексты через `t(...)`; новые ключи — сразу на 4 языка.
7. Только React Native API (никаких document/window/localStorage) — код един
   для web и native.
8. Файлы — только подписанные URL; доступ к сделке/чату — только участники.
9. Цвет CTA: текст тёмный на акценте (контраст на солнце) — и у зелёного,
   и у мандарина.
10. Водительский канон таб-бара не менять; Chat — всегда отдельная вкладка.

## 11. Что НЕ реализовано (открытые направления)

- VoIP/видео-звонки внутри приложения (сейчас 📞 = tel:). Нужен WebRTC-провайдер.
- Фоновый GPS при закрытом приложении (expo-task-manager, разрешение «Всегда»).
- Read-receipt «прочитано» отправителю показывается (✓✓), но без времени прочтения.
- Редактирование/удаление сообщений чата.
- CGR Трек 2: бронирование очереди из приложения (ждёт договора с ИУЦ).
- AI-ассистент в чате (авто-подсказки, сверка документов) — стратегическая цель.
- Оплата внутри приложения / эскроу — после беты.
