№ ЗТ-2026-01704182 от 22.04.2026 (заявитель — ТОО «ALLATAU AED»,

## 1. К какому сервису подключаемся

- **Сервис (ключ):** `CargoRuqsatAppsServiceSync`
- **Паспорт сервиса:** https://sb.egov.kz/services/passport/ORGAM-S-9317
- **Владелец сервиса / кому писать:** АО «Информационно-учётный центр»
  (`gosreestr.kz`). Контакт из письма: Купанова Л.К., тел. (7172) 55-29-81 (114),
  e-mail: `kupanova_l@gosreestr.kz`.

## 2. Обязательные условия ДО технического подключения (из письма)

Без этих двух пунктов доступ к боевому сервису не откроют:

1. **Положительные протоколы испытаний на соответствие требованиям
   информационной безопасности** (ИБ-испытания нашей ИС / мобильного приложения).
2. **Действующий договор с оперативным центром информационной безопасности
   (ОЦИБ)**.

Плюс формальное соответствие: законы РК «О персональных данных и их защите»,
«Об информатизации», ПП РК № 832 от 20.12.2016, приказ МИК РК № 123 от
29.03.2018 «Правила интеграции объектов информатизации ЭП».

## 3. Что нужно ПОЛУЧИТЬ у владельца сервиса (запросить у АО ИУЦ / Smart Bridge)

Просьба выдать/подтвердить:

1. **Спецификацию сервиса** `CargoRuqsatAppsServiceSync`: WSDL/OpenAPI, список
   методов и их контракты. Нам критично знать методы:
   - создание брони очереди (на пункт пропуска + слот времени),
   - отмена/изменение брони,
   - список моих броней / статус брони,
   - статус ТС в очереди по ГРНЗ (в очереди / вызван / пересёк / отозван),
   - справочники: список пунктов пропуска, зоны ожидания (АТС), доступные слоты.
2. **Механизм аутентификации** к Smart Bridge для этого сервиса:
   - сертификат ГОСО/mTLS (сертификат для СМШ) — какой центр выдаёт, формат;
   - либо сервисная учётка / токен — точный способ.
3. **Адрес(а) эндпоинтов**: тестовый контур (SB test) и боевой (SB prod).
4. **Доступ к ТЕСТОВОМУ контуру** Smart Bridge для интеграционного тестирования
   до боевого подключения (обязательно — прод открывают после успешных тестов).
5. **IP-адрес(а) для белого списка**: наш backend-сервер `185.22.65.11`
   (уточнить, нужно ли также добавить резервные/исходящие IP).
6. **Лимиты**: частота запросов (rate limit), максимальный объём, throttling —
   чтобы не упереться при поллинге статусов очереди.
7. **Регламент данных**: какие персональные данные передаются/принимаются
   (ГРНЗ, ИИН?), требования по хранению/маскированию (для соответствия ЗРК
   «О персональных данных»).

## 4. Что нужно ПОДГОТОВИТЬ на нашей стороне (наши программисты / ALLATAU AED)

1. Пройти **ИБ-испытания** и получить **протокол** (п.2.1) — организационно.
2. Заключить **договор с ОЦИБ** (п.2.2) — организационно/юридически.
3. Зарегистрировать нашу ИС на Smart Bridge (`sb.egov.kz`) и получить доступ к
   паспорту `ORGAM-S-9317`.
4. Получить и установить **сертификат mTLS** для СМШ на backend-сервере.
5. Настроить **исходящее подключение** с `185.22.65.11` к SB (после IP-whitelist).
6. Реализовать клиент к `CargoRuqsatAppsServiceSync` (SOAP/REST по спецификации)
   на backend — бронь, управление, статусы, справочники.
7. Логирование/аудит запросов (требование ИБ), хранение ПДн по регламенту.
