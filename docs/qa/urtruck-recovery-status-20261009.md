## 3. Что реально работает и что ещё нельзя объявлять готовым

Подтверждено владельцем: восстановленные голосовые, перевод после server recovery, доставка отдельного iPhone push и icon badge 3.
Ранее физически подтверждены Android chat delivery, удаление уведомления открытой комнаты, unread 3 → 0, сохранение посторонних уведомлений — на предыдущем кандидате.
Это не переносит PASS автоматически на новые бинарники, другой аккаунт или другую платформу.

13 на иконке и 9+ в Сделках не означают 13 непрочитанных сообщений чата. В проверенном серверном аккаунте это общие события reminder/no_bids.
Открытие списка сделок не является чтением всех таких событий. Нужна доступная лента, успешное подтверждённое чтение и одинаковый расчёт server/UI/native badge.
Если владелец хочет очищать все общие события при одном входе в приложение, это отдельное изменение продуктовой семантики; текущий patch не делает скрытое read-all.

Доставка до APNs/FCM и provider accepted не доказывает показ баннера, звук или физическое получение на устройстве.
В последнем read-only анализе были также APNs provider_not_configured failures и успешные sends. У ошибок не доказан единый актуальный источник, несмотря на наличие конфигурации в API process.
Это OPEN: сопоставить timestamp, event, process/provider config и retries. Не покупать новый push-сервис вместо проверки этой цепочки.

## 7. Как не ломать соседние разделы

Карта модулей уже сохранена: docs/qa/module-regression-control-20261009.md.
A1–A5 — сценарии водителя, B1–B4 — грузоотправителя, S1–S6 — общие сервисы. Идентификаторы служат карте ответственности; сами папки не гарантируют изоляцию.
Общие auth, deals, chat, badge, geography и API contracts надо проверять с обеими ролями.

Обязательный порядок любого следующего patch:
1. Читать AGENTS, ENGINEERING_CONSTITUTION, canon и это состояние; фиксировать branch/SHA, затронутые модули и rollback.
2. Воспроизвести конкретный дефект и указать ожидаемое поведение. Не делать массовую реорганизацию папок перед выпуском.
3. Проверить Graphify зависимости для nav/chat/MyTrips/db/i18n. SQL вручную дополняет AST coverage.
4. Сделать минимальный patch с регрессией на реальной логике, включая ошибки API, stale response и смену аккаунта.
5. Запустить target checks, обязательный полный CI и соседние критические сценарии обеих ролей.
6. Фиксировать source SHA каждого signed artifact; gate запускается ДО native build/upload.
7. На устройствах проверить critical paths того же бинарника. Потом выбирать store artifact, не случайный старый номер.
8. Обновить реестр: причина, исправление, tests, build, device proof, residual blocker. До этого дефект не VERIFIED.

#513 canonical workflow gates сейчас в ветке, не в main. Full CI 37916369198 и #514 37916840560 SUCCESS.
Их успешность не означает, что вся ветка слита или branch protection обеспечивает независимого reviewer: последний read-only protection check показал approving review count=0 и enforce admins=false.

1. P1 auth: воспроизвести «Сессия истекла» на сохранении машины; проверить refresh/token/401/retry, сохранить введённые данные. Отдельно keyboard avoidance.
2. P1 notification: проверить #512 на реальном API и iPhone; лента → read → canonical unread → icon; только прочитанное удаляется, чужая комната сохраняется.
3. Проверить provider_not_configured источник по одному событию; при необходимом отдельном server deploy выполнить backup/source guard/API-only restart/health/rollback.
4. Подготовить один native кандидат из согласованного полного SHA с #512–514 после успешных gates; не пересобирать разные ветки бессистемно.
5. Матрица iPhone/Huawei/OPPO: foreground другой экран, фон, блокировка, removed-from-recents; click → правильная комната; unread/badge grow/reset; аккаунт/роль/новое сообщение во время чтения.
6. Реальные RU↔ZH: 3–4 обмена туда и обратно, текст + настоящий голос + transcript + translation, города/цена/числа/время/отрицания. Mac synthetic speech не acceptance.
7. 249 стран на обоих native: поиск RU/ZH/EN/KK, ISO fallback, выбор/сохранение, Германия/Бельгия/Нидерланды/AX; размер/дизайн круглых флагов без изменений.
8. Обе роли: cargo/trip → bid → accept → одна общая deal/room → text/voice/docs → statuses; повторные запросы и запрет доступа третьему лицу.
9. Console: Android 16 KB, location/FGS forms/disclosure/privacy/demo-login; Apple review status. Только фактический результат переводит draft/submitted в public.
