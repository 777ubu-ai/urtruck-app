## Изменения

### GPS: пауза повторной отправки

- После network/timeout/неподтверждённого ответа голова очереди остаётся на месте.
- Пауза 30, 60, 120, 240 секунд, затем максимум 5 минут, с jitter ±20% до ограничения. Новый callback не обходит паузу.
- HTTP Retry-After в секундах или HTTP-date сохраняется; верхняя граница — сутки. Невалидное значение не отменяет обычный backoff.
- Счётчик и дата повтора хранятся отдельным атомарным ключом на sample. Restart и повторный append измерения не обнуляют задержку.
- Подтверждение/карантин удаляет запись повтора; данные и capturedAt не изменяются. Перед POST повторно проверяется авторизация.
- Ошибка одной сделки не мешает другой. Это не глобальная распределённая блокировка двух JS runtimes: серверная idempotency по sample_id продолжает защищать при совпавших отправках.

### Карта: прогресс на дороге

- Ближайшая вершина заменена проекцией на сегмент большой окружности. Разреженная геометрия теперь даёт промежуточное положение.
- Более 100 метров от дороги: прогресс/остаток неизвестны. При неоднозначном пересечении/петле тоже unknown; не выбирается случайный поздний участок.
- Допуск неоднозначности: кандидаты в пределах 25 м от ближайшего, различающиеся более чем на 200 м вдоль маршрута. Это консервативная оценка без истории движения, не полноценный навигационный map-matching.
- Малый шум обычной дороги не создаёт скачка на вершину. Финиш не округляется преждевременно до 100%.
- Provider distance_m согласует общую, пройденную и оставшуюся дистанции: сумма совпадает даже при упрощённой полилинии.
- Общий helper используется native и web. Web summary пересчитывается при новой GPS-точке независимо от отрисовки дороги и fitBounds.
- При смене маршрута/параметров машины прежний server route больше не используется во время ожидания ответа.
- driving_duration_s показан как «За рулём (оценка)», duration_s отдельно как «С отдыхом (оценка)», на четырёх языках. При отсутствии driving_duration_s поле неизвестно; время с отдыхом не подменяет движение.
