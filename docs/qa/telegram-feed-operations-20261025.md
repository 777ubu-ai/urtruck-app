## Получение свежего отчёта одной командой

Из нового рабочего дерева:

```bash
bash scripts/qa/telegram-feed-status.sh
```

Команда использует существующий SSH и передаёт Python через stdin. Файлы на
сервер не устанавливаются. SQLite открывается `mode=ro` + `query_only=ON`;
запуска/остановки сервисов, создания схемы, retry, purge и Telegram-запросов нет.
stdout — один JSON. Ошибки доступа и отсутствующие схемы не изображаются нулём.

Поля: окружение, marker SHA/хеши модулей, API/units, последнее успешное чтение
источника, день Алматы и 24 часа, этапы обработки, грузы/машины, очереди,
карантин, причины, актуальность, скорость/задержка, цель/дефицит, блокеры.
Статистика очистки честно неизвестна: `eligible_records: null`,
`configured: false`. Временные таблицы пока не классифицированы; удалять их нельзя.

Проверки: семь изолированных unittest PASS: раздельные счётчики, часовой пояс,
обе формы delivery timestamp, отсутствие PII/секретов и изменения хешей БД,
отсутствующие/внешние пути, редакция произвольных строк. Bash syntax и diff-check
PASS. Скрипт реально выполнен на сервере; `/health`/version HTTP200, JSON без
query errors. Это не полная backend/native/E2E приёмка бизнес-изменений.
