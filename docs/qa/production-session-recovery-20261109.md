## Причина и минимальное исправление

На точном ec27 воспроизведено: `regAPI.me()` возвращает null при401, а `refreshLevel()` сохраняет локальный вход. Новый regression сначала FAIL, после правки PASS. Явный AUTH_REQUIRED от канонического `/register/me` запускает восстановление входа. Сеть, таймаут,403 и5xx не выполняют выход. Поздний401 не отменяет новую сессию. Канонический запрос ограничен15секундами.

Дополнительная проверка production HTTPS выявила: listTrips(savedOnly:true) не передавал bearer и получал401 при действующей сессии. Исправлено симметрично listCargos: авторизация передаётся только для фильтра избранного; обычная выдача остаётся публичной. Regression сначала FAIL, после PASS; публичный HTTPS после исправления200/search_contract1.

Истечение сессии больше не вызывает обычный `signOut`, который удалял работу. Перед очисткой bearer сохраняются durable-маркер владельца/источника и проверенная копия общих форм. Boot и signIn завершают карантин до допуска следующего пользователя. Используется существующий PhoneV2 с сообщением `session_expired`.

Черновики чата и публикации разделены по API и ownerId. Одноразовое копирование legacy-форм допускается только на bootstrap после `/me200` того же исходного bearer и совпавшего владельца, без перезаписи нового ключа. Явный другой API, отказ, новый вход и смена владельца запрещают копирование. Оригиналы остаются сохранёнными; неизвестное происхождение legacy не называется доказанным production.

Legacy-очереди без доказанного владельца/окружения не отправляются автоматически. На401 очередь чата сохраняет сообщения без расхода retry. Лимит50, дедупликация и очистка разделены по владельцу/API. Generation фиксируется до постановки flush в очередь и проверяется после await. Guard проверяется также в chatAPI.send после чтения bearer. Идемпотентный client_msg_id и FSM не менялись.
