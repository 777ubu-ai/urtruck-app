## Подтверждённые проверки

### Вес — физический PASS

На Xiaomi через интерфейс создан QA-груз Алматы → Астана, 20 000 тонн, 105 м³, USD 1000. API/изолированная SQLite содержат `weight_tons=20000.0`, статус active; карточка «Мои грузы» и экран деталей показывают `20000 т` / `20 000 т`. Данные не делились на 1000. Это проверяет единицу от формы до отображения для нового QA-объявления; старые реальные записи не менялись.

Описание тестовой записи обновлено через интерфейс на `QA2P_20261017_20000T`, поскольку lab-фильтр скрывает обычный маркер `QA`. Это единственная запись, созданная и отредактированная в этой физической проверке; она не удалялась.

### Лента / ставка — BLOCKED, причина пока не установлена

На OPPO экран грузов загружается, маршрутные и ценовые фильтры отображаются, synthetic карточки ленты присутствуют. QA-груз с active статусом и специальным QA-маркером появился в UI после применения точной даты загрузки `20.10.2026`; он был открыт обычным нажатием. Изначально объявление не было среди первой видимой страницы после обновления/переключения вкладки; причина этого наблюдения не установлена, полнота ленты не заявляется.

На OPPO выбрано `$1 200`; «Отмена» в подтверждении оставила ставку в ожидании. Повторное открытие и подтверждение создало одну сделку: Xiaomi открыл чат грузоотправителя, OPPO показал один рейс «Принят» с той же ценой. После перезапуска OPPO сделка и QA-сессия сохранились. Это физически подтверждает базовый сценарий ставки/отмены подтверждения/принятия; HTTP status/request ID в ручном прогоне не сохранены. Встречная цена, отклонение, несколько комнат и отказ постороннему физически не проверялись.

Использованный lab backend запущен локально на `127.0.0.1:8005`, БД `lab/device-test.sqlite`, storage `lab/storage`; приложение обращается к `127.0.0.1:8002`, проброшенному через `adb reverse` на порт 8005. ### Контакт — код проверен, физически не принят

- `DriverDetail` использует авторизованный поиск доступных комнат; не создаёт комнату и не раскрывает телефон до принятой сделки. Пустой успешный ответ ведёт к предложениям, ошибка предлагает повтор, несколько сделок дают выбор, гостю показывается штатный вход.
- Действия accept/counter/reject блокируются от конкурентной повторной отправки; отмена подтверждения не вызывает API; ошибки сети, истёкшей сессии и уже обработанной ставки локализованы. FSM и серверные проверки не ослаблялись.
- Физический сценарий DriverDetail → доступные комнаты / пустой результат / повтор ошибки пока не выполнен.
