PRE-FLIGHT: физического known-good для общего кандидата нет. Изменены только экран внешней ленты, его тесты и две уязвимые сборочные зависимости. Перед правкой изучены AGENTS.md, инженерные каноны, Golden Baseline и CLAUDE.md. Выполнен AST-only Graphify-анализ затронутого экрана, описания карточки и вторичных кнопок: 52 узла, 79 связей. Полный проход репозитория был остановлен после извлечения файлов; полный граф не заявляется завершённым. Генерируемый граф в Git не включён.

## Найдено и исправлено

1. Четыре frontend-теста после объединения веток обращались к прежним идентификаторам контактов. Проверки обновлены под отдельный основной телефон и дополнительные контакты; сохранено реальное выполнение копирования всех контактов.
2. Security gate обнаружил уязвимые `glob 13.0.6` и `minimatch 10.2.6`. Overrides обновлены до `glob 14.0.2` и `minimatch 11.0.1`; lockfile пересоздан, повторный `npm ci` прошёл. Три проверки используют реальные glob/minimatch: sync/async, ignore/dot/brace, abort и extglob.
3. На 320 px при тексте ×1,5 слово «Отмена» разрывалось внутри фильтра. Действия фильтра теперь переносятся целиком. Действия карточки также сохраняют целые подписи при крупном тексте; при обычном размере три действия остаются в одном ряду, цели нажатия не меньше 44 px.
4. Четыре E2E-сценария ожидали отменённый минутный polling. Они проверяют текущий контракт: отсутствие запросов в простое, обновление через настоящий web AppState/visibility listener, сохранение фильтров и отсутствие дублей.
5. При заключительной QA2-проверке обнаружен скачок прокрутки. На web перевёрнуты данные, а не контейнер; прежняя формула применяла знак инвертированного контейнера. Исправлена компенсация смещения. Два детерминированных теста для ±50 px сначала упали на прежнем коде и прошли после исправления. E2E дополнительно проверяет отсутствие смещения в простое и после возврата; завершение начальной раскладки списка отделено от чтения пользователем.

## Воспроизведение

Использовать Node 20 и Python 3.12, чистый checkout выбранного SHA и изолированный локальный DB_PATH. Канонические команды:

```bash
npm ci
npm run test:unit
npm run lint
npm run audit:dependencies-and-forge-regression
npm run qa:center:quick
PYTHON_BIN=/path/to/venv/bin/python DB_PATH=/tmp/urtruck-isolated-qa.db \
  bash scripts/run_backend_tests.sh --isolated --disable-warnings
```

QA2 export должен выполняться с очисткой кэша: первая локальная сборка переиспользовала конфигурацию с выключенной лентой, что было ошибкой подготовки теста, а не доказательством неисправности клиента.

```bash
CI=true URTRUCK_BUILD_FLAVOR=qa2 URTRUCK_VERSION_NAME=1.0.12-qa2 \
EXPO_PUBLIC_API_URL=https://qa2.urtruck.kz \
EXPO_PUBLIC_WEB_URL=https://qa2.urtruck.kz \
EXPO_PUBLIC_EXTERNAL_FREIGHT_FEED_ENABLED=true \
URTRUCK_SOURCE_SHA=8dd733cedae873dd809edd16062e79dfca3a0915 \
  npx expo export --platform web --clear
node scripts/finalize-web-export.mjs
npx playwright test tests/e2e/external-freight-bookmarks.spec.js
```

Перед Playwright установить Chromium штатным `npx playwright install chromium`; при его недоступности явно указывать альтернативный executablePath и фиксировать версию. Наш локальный альтернативный запуск отключал запись видео, сохранял скриншоты и не менял проверки тестов. Для обязательного набора входа/сделок и publication replay использовать изолированные backend/proxy и beta export из `.github/workflows/quality-gate-reusable.yml`. При параллельных разных export сохранять отдельные каталоги: `EXTERNAL_FEED_TEST_DIST` и `URTRUCK_CONFIRM_DIST` должны указывать на соответствующую неизменяемую сборку. Не запускать тесты против каталога, который в этот момент пересобирается.

## Проверенные действия ленты

Для обеих ролей проверяются отдельные ленты грузов/машин, первый вход и возврат, сохранение/снятие сохранения, ошибки сохранения, все пять фильтров, применение/отмена/сброс, смешанные валюты, цена без обрезания, короткий и полный исходный текст, копирование контактов, Share и его отмена, обе ссылки магазинов, WhatsApp-черновик, выбор из нескольких телефонов, отсутствие угадывания кода страны, отсутствие запросов AI и записей в бизнес-объявления из действий ленты.

WhatsApp-проверка перехватывает открытие ссылки: реальные сообщения никому не отправлялись. Она не доказывает открытие установленного WhatsApp на телефоне. Неполный номер остаётся доступен для копирования; неизвестный код страны не подставляется.

## Почему пока нельзя заливать в магазины

1. [Quality Gate кода 8dd733c](https://github.com/777ubu-ai/urtruck-app/actions/runs/41240487617) завершился до выполнения: три задачи, у каждой `steps=[]`, runner name пустой. Предыдущая явная диагностика сообщала billing lock; текущий API не подтвердил снятие блокировки и не предоставил новую точную причину. Карта, сохранённая в настройках, сама по себе не доказывает успешную авторизацию платежа. Checks не отключались и не обходились.
2. Кандидат не устанавливался на QA2. Живые incoming/owned очереди, throughput, возраст ready и истёкшие pending в этой сессии через серверные базы не проверены. Старые значения из переписки не выдаются за текущие. Public `/health` с `ok` недостаточен для приёмки backlog.
3. Доступ к пользовательскому Mac через Desktop Commander заблокирован месячной квотой. Повторные вызовы после запрета не выполнялись. Huawei, Xiaomi и iPhone на этом SHA не проверены. Подписанные APK/AAB/IPA не собраны.
4. Store-номера не сверены с ASC/Play/EAS. Старые `app.json` 1.0.12/114 и QA2 Android 214494480 не подтверждают следующую допустимую версию. В предыдущем отчёте уже упоминались production 1.0.13(123) и QA2 iOS 1.0.14(124); магазинный откат недопустим.
5. Не доказаны на живых обезличенных сообщениях полнота импорта, recall водителей, составные объявления и фактическая очистка по TTL. Неопределённый тип нельзя объявлять грузом или свободной машиной догадкой. Количество сырых сообщений, сегментов, доставок и активных карточек — разные метрики.

## Дальнейшее исполнение

1. Владелец устраняет отказ авторизации карты/ограничение Actions в [GitHub billing](https://github.com/settings/billing/payment_information). Новая почта и подписка Copilot для этого не требуются. После исправления запустить обязательный Quality Gate на выбранном окончательном SHA.
2. Штатно продвинуть проверенный кандидат в `qa2/integration-candidate`. Узкий workflow `.github/workflows/deploy-qa2-external-feed.yml` запускать с этой ветки, её exact SHA и `confirmation=INSTALL_URTRUCK_FEED_QA2`. Он требует Quality Gate и approval среды QA2. Перед установкой — предусмотренные онлайн-копии SQLite; после — сверка SHA/хешей backend, мостов, adapter и health.
3. Два последовательных часовых замера на одной установленной версии: поступления, терминальные доставки, terminal expired, ready/backoff/expired pending, oldest ready age. Не выдавать истечения за доставки, не обнулять очередь вручную, не продлевать TTL перепубликацией. Пока есть старый backlog, он и возраст должны сокращаться; после разгрузки при сопоставимой нагрузке очередь не должна устойчиво расти.
4. Проследить реальные объявления обоих типов до активных карточек. Оценить причины review/reject на выборке исходных сообщений, восстановить пригодные непросроченные объявления идемпотентной повторной обработкой. Проверить контакты в конце составного сообщения, редактирования, дубли и срок хранения внешних объявлений 10 дней. Не менять срок пользовательских объявлений побочно.
5. Сверить номера магазинов и устройств, собрать подписанные бинарники из одного принятого SHA. На точных сборках проверить обе роли, девять языков на страницах/деталях, крупный шрифт, повторный запуск, фон/возврат, длинную прокрутку, Share и переход/возврат WhatsApp. Приложить модель/ОС/версию/SHA и настоящие снимки устройств.
6. Только после этой приёмки готовить Production и магазинную отправку. Текущий PR остаётся draft. Откат серверного кода — по штатному workflow, без восстановления старой SQLite поверх новых данных.

Полный запуск всех существующих web-spec, длительное нагрузочное испытание живого сервера и физическая матрица не заявляются выполненными. Результат этой работы — собранный и исправленный кандидат с воспроизводимыми локальными доказательствами и явно перечисленными оставшимися условиями выпуска.
