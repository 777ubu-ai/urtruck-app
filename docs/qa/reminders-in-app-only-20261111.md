# Напоминания только внутри приложения — 11.11.2026

Ветка fix/reminders-in-app-only-20261111, база 76247c003e9f09ef41b77ef8557c915c1ca4363b. Отдельный worktree; регистрация и ветка счётчика не изменялись.

## Подтверждённая причина production
Read-only SQLite показал 1400 попыток no_bids за трёхсуточное окно для 182 сочетаний пользователь/объявление; повторения есть во всех группах. Это не число пользователей или показов. Работающий scheduler запускает no_bids каждые 3 часа. Сравнивает SQLite CURRENT_TIMESTAMP с ISO-строкой через лексическое >, использует окно 20 часов вместо постоянного claim и не передаёт event_key в push_sender.send. Внутренняя дедупликация notifications не защищает независимый вызов push_sender.
Частота каждую минуту для конкретного пользователя не доказана. bid.expired — отдельное событие, повтор именно его не подтверждён.

## Изменение
Разделены решение о наличии записи inbox и разрешение внешней доставки. Только транспорт блокирует no_bids, inactivity/legacy reminder без маршрута, listing_lifecycle/expired и bid.expired. Новые сообщения, ставки, принятие, статусы сделки и сохранённые поиски остаются на прежней политике.
Защита применяется в send, send_to_devices и worker перед отправкой, включая старые outbox строки с event_type без data.event. Подавленные задания сохраняются как skipped_policy / in_app_only; журнал и записи пользователя не удаляются.
Истечение ставки продолжает создавать внутреннюю запись для участников с URL конкретной карточки и bid ID. Текст RU/KK/ZH/EN объясняет истечение срока ответа и предлагает открыть связанную карточку вместо неопределённого «проверьте архив».
Статусы, сроки, автопродление, данные объявлений, интерфейс регистрации, чат, GPS и provider credentials не менялись. Новая кнопка продления ставки не добавлена.

## Ограничения и продвижение
Production не изменён: он использует более старую реализацию, чем база этого PR. Нельзя копировать весь кандидат на production или менять shared sender из другого поколения без проверки зависимостей.
Нужны review и штатная интеграция минимального изменения, проверка точного runtime и наблюдение минимум полного цикла scheduler. Проверка на физических телефонах и подтверждение прекращения реальной рассылки пока NOT RUN.
Откат — revert отдельного коммита; без восстановления всей БД и без удаления новых данных. Откат политики снова разрешит нежелательные уведомления, поэтому решение об откате принимать с учётом инцидента.
