# Автоматическое продление собственных грузов и рейсов

Основание: дополнение владельца 07.11.2026 к выпуску — собственные объявления
водителя и грузоотправителя автоматически продлеваются на месяц. В существующей политике месяц
означает 30 суток UTC. База патча — PR #681, `0400a24d66e3ba6fd844d8241ee37ce8e0a5226c`.

## Итоговая политика

| Данные | Срок и действие |
|---|---|
| Собственный активный груз | Автопродление циклами по 30 суток, без нового ID и ручного обновления |
| Собственный активный рейс/предложение машины | Автопродление циклами по 30 суток, без нового ID и без действий водителя |
| Внешние Telegram грузы и машины | 30 суток от исходного `source_published_at` по PR #681, без продления при импорте |
| Каталог перевозчиков | Отдельное хранилище, TTL объявлений к нему не применяется |

`get_conn()` уже вызывает housekeeping: за один UPDATE переносится `published_at`
активного груза/рейса на начало текущего 30-дневного цикла. Пропущенные циклы сворачиваются;
повторный вызов не меняет запись. `created_at`, дата выезда, ID и владелец сохраняются.
Периодические задачи используют тот же DAL; API не требует открывать приложение.
Проверки API и UI поддерживают активное объявление также до очередного housekeeping,
включая границу срока и устаревший клиентский кэш.

Архивные, снятые, отменённые и занятые грузы/рейсы не восстанавливаются. Активная сделка
защищает публикацию от housekeeping. Ставки сохраняют отдельный срок 48 часов,
историю, проверки ролей и атомарное принятие. Lifecycle не предлагает вручную
продлевать автоматически продлеваемое объявление; уже поставленное напоминание о старом
сроке блокируется delivery policy. `no_bids` сохраняет один event ID на объявление.

## Проверка и продвижение

Новые behavioral regression: точная UTC-граница/микросекунда до неё, +05:00,
пропущенные циклы, сохранность идентичности, повторный запуск, архив, активная
сделка, отдельный TTL ставки, public API, создание/принятие предложения и lifecycle.
Прежние FSM/security regression сохранены; ожидания 30-дневного истечения активных
грузов/рейсов заменены проверкой автоматического продления обеих ролей. Graphify AST-only: 14065 nodes / 32720 edges; SQL parser
недоступен, схемы и SQL прочитаны напрямую; Gradle не относится к патчу.

Миграций схемы и массового восстановления нет. Сначала независимый review и CI
PR #681, затем review связанного патча и штатное QA2-продвижение с backup/restore
и health. Владелец дал условное разрешение production/store выпуска только после
всех обязательных review/CI/QA2/native/backup/production gates; непроверенный критический
сценарий блокирует выпуск. Удаление данных и новые расходы не разрешены.

Откат: revert патча и штатный code-only deploy предыдущего SHA. БД и историю не
перезаписывать. Уже продлённый `published_at` остаётся действующим ещё до 30 суток;
старый код снова начнёт истекать по окончании этого срока. Старые APK без нового
helper получают обновлённую дату после server housekeeping/refresh; офлайн-кэш
старого APK на границе требует отдельной физической проверки.

## Результат security review

Независимое review fb097100 выявило P1: объявления удалённого владельца могли
продлеваться бессрочно. Для deleted status/role продление запрещено; после исходного
срока запись переводится в expired без удаления. Public list/detail скрывают её
сразу, новые/существующие ставки отклоняются тем же DB connection, optional
уведомления подавляются. Участники старых сделок сохраняют исторический доступ;
операционные события сделок не блокируются этой политикой. Регрессии обеих ролей
проверяют реальные delete_account на синтетической SQLite, оба show_demo режима,
прямой URL, housekeeping, ставки, уведомления и сохранность истории.

Остаточный P2 повторного review: digest saved_search тоже исключает deleted owner,
а доставка события с явным listing ID без доступного объявления блокируется
вместо перехода к legacy from/to. Fallback сохранён событиям без listing ID.
