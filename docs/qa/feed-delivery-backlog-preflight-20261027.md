## Stop the line: физический дефект сборки 473

На Xiaomi сборка `1.0.12-qa2 (214494473)`, frontend e51bc84e, API 0c4f116e: нажатие «Откуда» вызывает клавиатуру, но sheet отсутствует в доступной и видимой иерархии. В установленном RN 0.86.3 `StyleSheetExports.js` экспортирует `absoluteFill`, но не `absoluteFillObject`; react-native-web продолжает экспортировать оба. Причина — spread неопределённого свойства давал слой без абсолютных границ. Это подтверждённая регрессия, не PASS нового Android.

Адресное исправление: явные `position/top/bottom/left/right` для двух слоёв только ExternalFreightFeedScreen; runtime-тест с native StyleSheet без устаревшего свойства проверяет геометрию. Остальные экраны защищены от попутных правок. Новый бинарник имеет versionCode 214494474; сборка TestFlight 40546968460 остановлена до исправления. Huawei 473 остановлен на защищённом подтверждении Huawei, установка не завершена; требуется новый кандидат и отдельный физический повтор обоих телефонов.

Оба физических телефона подтверждают `arm64-v8a` через `ro.product.cpu.abilist`. Для повторного внутреннего APK добавлен явный выбор `qa_abi=arm64-v8a`: он сокращает сборку до архитектуры этих устройств. Значение по умолчанию `all` сохраняет прежний универсальный APK; store/release workflow не меняется.

Дополнительно на настоящей карточке 52bf19e7 найден неверный тип: перенос «надо 3 фуры / готов груз» ошибочно трактовался как «фуры готовы». Уточнён спрос на фуры и обратный порядок «готов груз», добавлены две регрессии. Parser revision v12 запускает идемпотентную пересверку старых записей.

В фактическом APK 473 подтверждён Android `windowSoftInputMode=adjustResize` (0x10). Для вложенного слоя убрана повторная Android-компенсация высоты клавиатуры по принятому паттерну EditCargoModal; iOS получает offset, равный измеренному положению панели под полосой фильтров. Это проверяется разными runtime-ветками и требует физического повторения.
