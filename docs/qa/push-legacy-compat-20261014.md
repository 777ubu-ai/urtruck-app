## Наблюдение о старом алгоритме

Исторический `_dedupe_for_dual` убирал Expo row только при точном совпадении непустого `device_id` с native row того же user, но пропускал ambiguous Expo rows без `device_id`. Новый вариант должен fail closed для пустых ID, если у владельца уже есть native targets. При полном отсутствии native targets Expo-only клиенты остаются обслуживаемыми.
