## Согласованный интерфейс
1. Небольшая кнопка «Лента грузов» сверху слева на CargoFeedScreen, на уровне текущего меню справа; размер существующей шапки и карточек не менять.
2. Отдельный stack-экран ExternalFreightFeed на весь экран с Back, без нижнего таббара.
3. Вверху пять компактных фильтров: Откуда, Куда, Кузов, Дата, Цена. При большом шрифте допустима горизонтальная прокрутка строки вместо обрезания или уменьшения системного масштаба.
4. Откуда/куда: страна или город с переиспользованием существующего справочника; не угадывать неоднозначный пункт.
5. Дата — календарь ДАТЫ ПУБЛИКАЦИИ, «Сегодня», «Вчера», диапазон. Дата погрузки показывается отдельно только при явном наличии в исходнике.
6. Цена — диапазон и сортировка выше/ниже в выбранной валюте. Разные валюты не сравнивать численно; договорная/неуказанная цена сохраняется отдельно.
7. Карточка: маршрут, цена/валюта, наименование груза, вес/объём, кузов, количество машин, готовность/погрузка, контакты и время публикации — только имеющиеся данные.
8. Длинные условия/исходный текст раскрываются «Ещё» внутри той же карточки, закрываются «Свернуть». Нет отдельной страницы заявки.
9. Контакты — текст с возможностью копирования. Нет кнопок связи, переписки, ставок, добавления, перехода в сделку.
10. Копирование не требует доступа к контактам телефона. Геолокация, карта и GPS здесь не запускаются.
11. Новые интерфейсные строки RU/KK/ZH/EN; исходные объявления не переводить автоматически. Светлая и тёмная темы, safe areas, font scale 1.0/1.3/1.6.

## Данные и подключение
Отдельная сущность external_freight_posts, не строки marketplace cargos/trips/deals и не фиктивные аккаунты владельцев.
Минимальные поля: id, source_id, source_message_id, segment_id, source_published_at, ingested_at, expires_at, original_text, origin/destination (nullable normalized IDs + исходные подписи), cargo_name, body_types, weight/volume, vehicle_count, loading_date (nullable), ready_text, amount/currency (nullable), contacts, status.
Доступ на запись только у доверенного серверного импортёра/администратора. Пользователь приложения не получает importer credential и не может писать через прямой API.
Адаптер к существующему агенту с отдельным состоянием повторов/доставки в приложение. Работа Telegram-публикатора не зависит от доступности API UrTruck.
Импортировать только отобранные сообщения из согласованных источников; не запускать второй сборщик. Одно сообщение с несколькими маршрутами разбивать на сегменты, связывая правильные контакты. Нечёткие/сомнительные записи оставлять для служебной проверки.
Идемпотентность по source_id/source_message_id/segment_id; контентные повторы учитывать отдельно, не склеивать автоматически разные цены и контакты.
Срок активности 120 часов от исходной публикации, а не момента загрузки. Повтор импорта не продлевает срок. Истёкшие скрываются прямо в read-query даже если cleanup не запускался. Физическая очистка отдельной ограниченной задачей только новых данных.
Даты/телефоны/валюту/географию не выдумывать. Неоднозначность «Алашанькоу/Бахты», неверные флаги и «на 23 число» без месяца требуют сохранения исходного текста/явного решения, а не догадки.
Не подключать новые платные сервисы/LLM.

## Производительность и изоляция
Серверная фильтрация и индексы; cursor pagination с фиксированным tie-break id, страницы по 30, max 100.
FlatList/виртуализация; фильтры с debounce и отменой старых запросов, защита от запоздалого ответа. Нет скачивания всей ленты, секундного polling или фоновых запросов при blur/background.
Проверить синтетическую активную ленту до 100000 записей (плановая модель 20000/сутки за 5 суток, не измеренный объём). Зафиксировать реальные latency и планы запросов, не обещать неподтверждённые метрики.
Ограничить импорт партиями и backoff. Сбой агента не должен блокировать основной API.
Отдельный feature flag, отключённый до QA. Отключение ленты не останавливает Telegram-публикацию и сделки.

Новые: src/screens/ExternalFreightFeedScreen.js, src/utils/externalFreightAPI.js, отдельные компоненты карточки/фильтров и чистые функции; backend/api/external_freight.py, backend/database/external_freight_dal.py, аддитивная миграция/инициализация только новых таблиц, адаптер импорта и связанные тесты.
Точечные существующие: CargoFeedScreen.js (кнопка), RootHeader.js (необязательный left slot только для этой страницы), AppNavigator.js (stack registration), i18n.js (новые ключи), backend/main.py (подключение отдельного router).
Точный список уточнить после AST/Graphify анализа и зафиксировать перед кодом. Правило CLAUDE.md Graphify-gated changes требует анализа и подтверждения scope владельцем до изменения защищённых навигации/Feed/i18n/БД. Данный документ — конкретное scope для такого согласования.

Поэтому контракты назад совместимы, left slot по умолчанию отсутствует, импорт отделён, записи marketplace не меняются.
Защищены: текущие вкладки/размеры/дизайн карточек, Auth, FSM, сделки/чаты, расходы, Push, GPS, карта, документы, переводчик, зависимости, CI/deploy workflow, старые таблицы и рабочие данные.

## Приёмка
- Импорт сегментов/контактов, повтор/редактирование/перезапуск без дублей; данные с неизвестными датами/ценой не теряются.
- Отказ обычному пользователю на запись; отсутствие секрета импортёра в клиенте; входные лимиты, параметризованные SQL.
- Граница 120 часов, timezone, одновременная пагинация и новые записи без повторов/пропусков в установленном snapshot порядка.
- Все пять фильтров вместе, сортировка внутри валюты, сброс/Back сохраняют понятное состояние; stale response не подменяет фильтр.
- «Ещё/Свернуть», длинный маршрут/телефон/цена, large font, dark mode; реальный screenshot до/после на iPhone и Android.
- Уход/фон отменяет загрузку; GPS и background tracking отсутствуют; возврат не теряет позицию списка.
- Регрессия прежних навигации, ролей и грузов; не объявлять PASS по скриншотам-макетам.
- Сначала локальная/QA среда с синтетическими данными, затем ограниченный импорт с отдельным разрешённым источником. Никакого deploy, новой магазинной сборки или активации production в рамках подготовки ТЗ.

## Уточнение владельца 20.10.2026, 22:55 Алматы
Владелец одобрил предыдущий scope. Дополнение для согласования: общий раздел объявлений с двумя типами cargo/vehicle; водитель по умолчанию видит «Лента грузов», грузоотправитель — «Лента машин». Это не переключение роли и не создание второго аккаунта. Один backend и набор общих компонентов, отдельные типы записей и контекст фильтров. Для client-входа потребуется также точечная кнопка в существующем FeedScreen.js; это расширение исходного списка изменяемых файлов.
Прямая read-only проверка feed.py: eligible() использует широкие CARGO/ROUTE regex. Отдельной классификации груз/свободная машина нет. Её не объявлять реализованной.
Классификация намерения: «нужен тент/ищу машину/груз готов» => cargo; «свободная машина/есть тент/ищу груз/порожний» => vehicle. Не классифицировать по слову «тент» или «груз» отдельно. Сообщения с обоими типами разделять только при явных границах; сомнительные отправлять в служебную проверку. Закрытие заявок проверять для обоих типов, включая «машина занята»/«груз найден». При переходе типа не смешивать карточки и запоздалые ответы.
Для машины использовать фактические поля исходника: текущее местоположение, желаемое направление, кузов, грузоподъёмность/объём, количество машин, дата готовности, цена если указана, контакты. Календарь остаётся датой публикации. Отсутствующие данные не выдумывать.
Локализация интерфейса RU/KK/ZH/EN сразу. Вариант перевода исходного объявления: только явное «Перевести» в раскрытой карточке на выбранный язык, оригинал доступен, результат кэшируется по версии исходного текста и языку. Не запускать перевод при импорте, polling или прокрутке. Существующий переводчик чата нельзя вызывать обходом прав комнаты; для ленты потребуется отдельный защищённый контракт с лимитами и сохранением номеров/сумм/единиц. Новые платные сервисы и платные live-проверки без разрешения не запускать.
