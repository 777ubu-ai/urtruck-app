# UrTruck: Политика хранения и удаления данных

> Документ описывает, какие данные UrTruck собирает, как долго хранит
> и что происходит при удалении аккаунта. Соответствует Apple App Store
> Guideline 5.1.1(v) и Google Play Data Safety.

## 1. Собираемые PII

| Поле | Цель | При удалении |
|------|------|-------------|
| Телефон | Авторизация OTP | Псевдонимизируется → `deleted_{id}` |
| Email (если указан) | Резервный вход | NULL |
| ФИО | Идентификация в сделках | NULL |
| ИИН | Верификация водителя | NULL |
| Город | Геотаргетинг | NULL |
| О себе (about) | Профиль | NULL |
| Номер ТС | Идентификация рейса | NULL |
| Экстренный контакт | Безопасность | NULL |

## 2. Документы и файлы

| Объект | Хранение | При удалении |
|--------|----------|-------------|
| Фото удостоверения (id_front/back) | Storage (Supabase/S3/local) | Файл удаляется, URL → NULL |
| Фото прав (license_selfie, license_back) | Storage | Файл удаляется, URL → NULL |
| Фото ТС / кабины | Storage | Файл удаляется, URL → NULL |
| Загранпаспорт / TIR / CMR | Storage | Файл удаляется, URL → NULL |
| Аватар | Storage | Файл удаляется, URL → NULL |
| Фото грузов/рейсов | Storage | Файлы удаляются best-effort |
| Вложения чата | Storage | Не удаляются (часть сделки, см. §5) |

## 3. Операционные данные

| Данные | Хранение | При удалении |
|--------|----------|-------------|
| Сессии (reg_sessions) | SQLite | Удаляются (все сессии) |
| Push-токены (native/web) | SQLite | Деактивируются (active=0) |
| OTP-коды | In-memory (rate limiter) | Очищаются при рестарте |
| GPS-координаты (deal_locations) | SQLite | Удаляются |
| Избранное (favorites) | SQLite | Удаляются |
| Сохранённые поиски | SQLite | Удаляются |

## 4. Данные, сохраняемые после удаления

Следующие данные **не удаляются** — они необходимы для:
- Целостности бизнес-записей (перевозки, сделки)
- Аудиторского следа (legal compliance)
- Защиты от мошенничества

| Данные | Причина сохранения |
|--------|--------------------|
| Строка drivers_registration (id, status=deleted, role=deleted) | FK-ссылки из deals/chat, anti-fraud |
| Записи deals / deal_events | Логистический аудит, претензии |
| Записи cargos / trips / bids | Бизнес-история |
| Записи reviews (отзывы) | Публичная репутация, anti-fraud |
| Записи blacklist | Безопасность |
| Записи consent_audit | Юридическое подтверждение согласия |
| Чат-сообщения (обезличен sender_name) | Аудит сделки |

**Чат:** `sender_name` заменяется на «Удалённый пользователь». Содержимое
сообщений сохраняется как часть бизнес-записи сделки.

## 5. Процесс удаления аккаунта

1. Пользователь нажимает «Удалить аккаунт» → подтверждение
2. Backend: деактивация push-токенов (best-effort)
3. Backend: сбор ссылок на storage-объекты
4. Backend: обезличивание PII в drivers_registration
5. Backend: удаление сессий
6. Backend: удаление GPS-координат, избранного, поисков
7. Backend: обезличивание sender_name в чатах
8. Backend (вне транзакции): удаление файлов из Storage
9. Frontend: очистка локального хранилища, logout

Процесс идемпотентен — повторный вызов безопасен.

## 6. Сроки хранения

| Категория | Срок | Основание |
|-----------|------|-----------|
| Активный аккаунт | Бессрочно (пока пользователь не удалит) | |
| Удалённый аккаунт (обезличенная строка) | 5 лет | Транспортный аудит |
| Deal/cargo/trip записи | 5 лет после завершения | Претензионный срок |
| Consent audit | 5 лет | Юридическое требование |
| Server logs | 90 дней | Операционная необходимость |
| Sentry events | 90 дней (Sentry retention) | |

## 7. Контакт

Запросы на удаление данных: через приложение (кнопка «Удалить аккаунт»)
или по email поддержки, указанному в Privacy Policy.
