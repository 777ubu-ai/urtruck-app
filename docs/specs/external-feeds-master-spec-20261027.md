# Техническое задание: лента грузов и лента машин UrTruck

Версия: 1.0. Дата: 27.10.2026. Основание: сообщения владельца и два снимка проблем с контактами и нижним окном фильтра.

Статус документа: требования и план приёмки. Этот документ не означает, что перечисленные исправления уже выполнены. Реализация закрывается отдельными проверенными изменениями.

## 1. Цель

Пользователь открывает нужную ленту, видит максимум доступных объявлений из согласованных Telegram-источников, находит маршрут и машину/груз, читает весь исходный пост и получает все доступные в нём контакты. Фильтры, клавиатура, закладки и обновления работают без скрытых обязательных действий и без необходимости нажимать «Сброс» для выхода из окна.

Основное правило: отсутствие распознанной цены, кузова, телефона или направления не должно само по себе скрывать согласованный исходный пост. Неопределённое поле и отсутствие исходного объявления — разные состояния.

## 3. Кому какая лента предназначена

| Пользователь | Что он ищет | Что получает |
| --- | --- | --- |
| Водитель / перевозчик | Груз для перевозки | Лента грузов: объявления грузовладельцев, которым нужна машина |
| Грузоотправитель / грузовладелец | Машину / перевозчика | Лента машин: предложения перевозчиков о свободной машине и готовности забрать груз |

Примеры, обязательные для проверки:

- «Ищу груз, машина свободна» → предложение машины → лента машин грузоотправителя.
- «Нужна фура, груз готов» → запрос на перевозку → лента грузов водителя.
- «Нужен водитель на постоянную работу» → не подтверждает наличие свободной машины; не подменять этим карточку готового транспорта.
- «Тент 22 т» без контекста не доказывает ни наличие машины, ни наличие груза.

Роль в шапке, нижнем меню, запросе API и фактическом содержимом должна совпадать. При смене роли нельзя оставлять старую выдачу другой роли в памяти.

## 4. Telegram-источники и максимальное наполнение

### FEED-SRC-01. Основной согласованный чат

Основной явно указанный владельцем источник: `https://t.me/UrTruck_obyavleniya`. Для его доступных объявлений требуется прямой путь получения → сохранения → публикации в приложении. Не требовать повторного одобрения только из-за пустых разобранных полей.

Проверить сбор новых сообщений, правок, пересланных сообщений, подписей к медиа и многомаршрутных подборок. Служебные сообщения самого бота отличать от объявлений, чтобы приложение не заполнялось собственными кнопками скачивания.

### FEED-SRC-02. Внешние согласованные каналы

Составить фактический реестр источников: ID/username, доступность, последняя успешная загрузка, число новых сообщений за день и причина остановки. Число каналов в конфигурации не выдавать за число работающих каналов.

Параллельный поиск машин использует доступные согласованные источники. Не отключать действующий сбор грузов при запуске поиска машин.

### FEED-SRC-03. Полнота доставки

- Пустая цена, неизвестный кузов или неполный маршрут не блокируют карточку собственного отобранного потока.
- Не отправлять весь поток в блокирующую «ручную проверку» из-за неизвестного поля.
- Если тип поста неоднозначен, сохранить и показать исходник с понятным обозначением неопределённости; не утверждать, что это доказанно свободная машина.
- Не дублировать неопределённый пост в обоих счётчиках как два независимых объявления.
- Явное закрытие/удаление автором обрабатывается отдельно от отсутствующего поля.
- Для каждого доступного исходного поста должен быть объясним результат: опубликован, обновлён, точный дубль, закрыт источником, ожидает доставки или ошибка с указанной причиной.

## 5. Полный исходный пост — обязательный контракт

### FEED-TEXT-01. Сохранение

Сохранять исходный текст без обрезки: строки, эмодзи, телефоны в начале/середине/конце, общие условия, подписи, ссылки и контактные строки. Поле для разбора маршрута и исходник для чтения пользователем не должны подменять друг друга.

Для нескольких маршрутов разрешены отдельные карточки. Каждая должна давать доступ к полному исходному посту и сохранять собственные маршрут/цену/вес, разобранные из её блока. Цена одного блока не становится ценой соседнего.

В карточке допустим краткий обзор. Кнопка «Показать полностью» обязана раскрывать весь сохранённый исходник. Если введена отложенная загрузка подробностей, показывать загрузку/ошибку и повтор запроса; не называть укороченный фрагмент полным текстом.

### FEED-TEXT-02. Длинные посты и медиа

- Поддержать длинные подборки в пределах фактических лимитов источника.
- При превышении внутреннего ограничения не обрезать молча: сохранить полный объект или связанные части и обеспечить чтение целиком.
- Сохранять подпись к фото/документу. Если телефон находится только на изображении, учитывать это в аудите и предусмотреть просмотр исходного медиа/извлечение через доступный локальный OCR. Нельзя считать такой случай «телефона нет» только по пустому caption.
- Телефонные ссылки и Telegram entities проверять вместе с обычным текстом; видимый номер не должен пропадать из-за формата ссылки.

### FEED-TEXT-03. Повторный разбор

Новая версия parser должна доходить до уже опубликованных карточек. Повторная обработка сохраняет ID, закладки, исходную дату, права доступа и состояние закрытия. Не создавать новый дубль при каждом запуске.

После удаления исходного поста его полная копия тоже должна корректно закрываться/очищаться по действующему контракту; не оставлять номер в скрытом дополнительном поле payload.

## 6. Телефоны: извлечение, отображение и восстановление

### FEED-PHONE-01. Форматы

Поддержать:

- номера с `+` и без него;
- номера с `8` и `7`, международные коды, местные номера;
- короткие номера из 6–9 цифр в контактной строке и подтверждённые пользователем самостоятельные 7–8-значные строки в любой части поста;
- пробелы, неразрывные пробелы, скобки, дефисы, точки, переносы и невидимые разделители;
- Unicode-цифры и цифры с emoji/keycap-оформлением;
- несколько номеров, подписи Telegram/WhatsApp и имя после телефона;
- номер в середине, в общей шапке, перед последней строкой и в самом конце.

Сохранять написание источника для пользователя. Нормализованный вариант использовать для сравнения и удаления дублей. Не угадывать код страны у короткого номера.

Не принимать за телефон явно подписанные цену, вес, объём, дату, количество машин, номер заказа или госномер. Ошибка извлечения не блокирует сам пост: полный текст остаётся доступен.

### FEED-PHONE-02. Контакты многомаршрутного поста

1. Явный локальный номер прикрепляется к своему блоку.
2. Явный общий номер показывается для всех относящихся к нему маршрутов.
3. Если номера есть в исходном посте, но привязка к отдельному маршруту не доказана, показать их в карточке как **«Контакты исходного поста»**, сохранив контекст в полном описании.
4. Не показывать «Прямой контакт не указан» как единственный результат, когда ниже уже доступен распознанный номер.
5. Не переносить номер из другого сообщения/другого автора без связи с текущим постом.
6. Если номер не найден после проверки доступного исходника и медиа, оставить реальный доступный Telegram-контакт/ссылку источника и понятное состояние, без выдуманного номера.

Это снимает блокировку из-за неопределённой привязки: номер доступен пользователю, но не выдается за доказанный прямой контакт конкретного маршрута.

### FEED-PHONE-03. Показ и действия

- Все найденные номера доступны в свёрнутой карточке либо в явно обозначенном раскрываемом блоке контактов.
- Копирование копирует выбранный номер целиком и показывает понятное подтверждение.
- Если доступен звонок, использовать проверенный `tel:`; короткий местный номер не дополнять произвольной страной.
- Обновление карточки не стирает уже подтверждённый контакт при временном сбое разбора.

### FEED-PHONE-04. Полная ревизия существующих записей

Проверить все активные карточки обоих типов, а не выборку из нескольких объявлений. Очерёдность:

1. Исправить 484 подтверждённых случая «номер есть в полном тексте, поле контакта пустое».
2. Разобрать 3 346 случаев без распознанного номера по группам: формат цифр, местный номер, Telegram entity, медиа, неполный локальный исходник, контакт только в Telegram, действительное отсутствие номера в доступном посте.
3. Для 135 записей без локального исходника попытаться получить исходное сообщение по его идентификатору. Недоступный источник помечать как непроверенный, а не как успешно восстановленный.
4. Обновлять существующую запись с резервной копией, без удаления объявления и потери закладки.
5. Повторить полный аудит. Для каждого оставшегося пустого поля должна быть причина и доступный исходник/доказательство невозможности получения.

Критерий приёмки: **0 необъяснённых случаев, когда номер распознан в доступном исходнике, но недоступен пользователю в карточке и полном описании.** Общий процент карточек с телефоном публикуется как факт, не как обещание наличия номера у каждого автора.

## 7. Отдельный поток поиска водителей и свободных машин

### FEED-DRIVER-01. Назначение

Запустить отдельную логическую обработку предложений перевозчиков параллельно сбору грузов. Она должна находить сообщения с намерением перевезти груз, а не только объявления с точной фразой «свободная машина».

Отдельный поток — не обязательно второй независимый Telegram-клиент. Допустим общий сборщик и отдельная очередь/классификатор машин. Обязательны отдельные метрики и независимое продвижение очереди, чтобы большой поток грузов не вытеснял машины.

### FEED-DRIVER-02. Словарь положительных сигналов

Обязательные русские варианты:

- «машина готова», «машина свободна», «фура свободна», «тент свободен», «реф свободен»;
- «ищу груз», «ищем груз», «нужен груз», «нужна загрузка», «ищу обратный груз»;
- «заберу груз», «возьму груз», «доставлю товар», «перевезу груз», «готов перевезти»;
- «есть машина», «есть свободная машина», «предлагаю машину», «предлагаем транспорт»;
- «порожний», «освободился», «освободимся», «готов к загрузке», «еду пустой»;
- предложение попутной/обратной перевозки при явной доступности транспорта.

Учитывать окончания, опечатки, дефисы, регистр, эмодзи и переносы. Уже имеющиеся сигналы `yuk kerak`, `mashina bor`, `жүк іздеймін`, `бос көлік`, `available truck`, `looking for cargo` покрыть реальными примерами из согласованных каналов. Дополнение словаря других языков принимать после проверки на реальных объявлениях.

### FEED-DRIVER-03. Контекст и исключения

- «Нужна машина», «ищу перевозчика», «фура керек» в значении запроса машины — это спрос на перевозку, а не предложение свободного транспорта.
- «Машина не свободна», «занят», «в ремонте», «освободится через неделю» не равны доступности сейчас. Дата готовности сохраняется явно.
- Продажа машины, запчастей, пассажирское такси и вакансия водителя не должны выдавать ложную свободную фуру.
- Смешанный пост с грузами и свободными машинами разбирается по блокам намерений; каждый блок получает правильный тип и доступ к полному исходнику.
- Название города, цена или кузов без контекста не определяют тип сами по себе.

### FEED-DRIVER-04. Результат

Показывать грузоотправителю: местонахождение машины, желаемое направление/«любое», дату готовности, кузов, грузоподъёмность, объём, количество машин, контакты и полный пост — всё, что действительно указано. Неизвестные поля не заполнять выдуманными данными.

Справочник перевозчиков выводить отдельным типом «Контакт перевозчика; наличие машины уточняйте». Его нельзя считать свежей заявкой о свободном автомобиле.

### FEED-MODAL-01. Открытие и выход

- Окно открывается первым нажатием на выбранный фильтр.
- При пустом поле можно закрыть окно без ввода и без сброса.
- «Отмена» закрывает окно и клавиатуру, не меняя применённые фильтры.
- Тап по затемнению вне окна закрывает окно. Активная область закрытия не должна перекрываться невидимым View.
- Добавить очевидное закрытие: крестик и/или работающий жест вниз за ручку. Декоративная ручка не должна обещать неработающий жест.
- Android «Назад»: сначала допустимо закрыть системную клавиатуру, следующим нажатием — окно; фильтры не сбрасываются.
- Тап по другому верхнему фильтру переводит к нему без обязательного сброса. Окно не должно превращать видимые верхние кнопки в неработающие элементы без понятного выхода.
- Повторный тап по текущему фильтру закрывает его окно, если такой элемент остаётся доступным.

### FEED-MODAL-02. «Найти», «Отмена», «Сброс»

| Действие | Ожидаемый результат |
| --- | --- |
| Открыть пустой фильтр → «Отмена» | Закрыть окно; выдача и ранее применённые условия сохранены |
| Открыть пустой фильтр → «Найти» | Закрыть окно без ошибки; отсутствие условия допустимо |
| Изменить значение → «Отмена» | Отменить черновик, сохранить прежнее применённое значение |
| Изменить значение → «Найти» | Применить, закрыть окно/клавиатуру, загрузить первую страницу |

При открытой клавиатуре кнопки «Отмена», «Найти», закрытие и переходы должны срабатывать первым нажатием, а не только снимать фокус.

### FEED-MODAL-03. Выделение и геометрия

- Применённый верхний фильтр имеет текст выбранного значения, зелёное выделение и видимое состояние активности.
- Внутри окна выбранный вариант отмечен галочкой/активным состоянием. Черновик не выдаётся за уже применённый фильтр до нажатия «Найти».
- Кнопки и поле видны над клавиатурой; safe area и системные кнопки не перекрывают ввод.
- Список кузовов и длинные варианты прокручиваются; последняя строка и произвольный ввод доступны.
- После закрытия не остаётся невидимого слоя, который перехватывает нажатия по ленте.

## 9. Правила пяти фильтров

### FEED-FILTER-01. Откуда и куда

Свободный ввод города/страны, выбор из подсказок и отсутствие значения допустимы. Сохранять введённый пользователем текст. Проверять разные регистры, пробелы, скобки с областью, известные варианты написания и транслитерации. Не ограничивать пользователя только городами справочника.

Поиск по направлению не должен случайно искать только в первой загруженной странице. Неопределённый маршрут остаётся видимым без фильтра; при поиске использовать корректно разобранное направление, а для неразобранного исходника — объяснимый текстовый поиск с обозначением неопределённости.

### FEED-FILTER-02. Кузов

Предустановленные типы и поле «Другой кузов / впишите свой». Работают синонимы и несколько допустимых типов из объявления. Произвольная строка ищется и в доступном полном исходнике. Пустое значение не блокирует поиск и закрытие окна.

### FEED-FILTER-03. Дата

В текущем контракте фильтруется дата публикации исходного сообщения; интерфейс должен это объяснять. Не подменять её датой импорта или восстановления. Дата погрузки/готовности показывается отдельным полем, если указана.

Проверить «Сегодня», «Вчера», диапазон, обе границы, очистку и разницу часовых поясов. Ошибка диапазона объясняется пользователю, окно не зависает.

### FEED-FILTER-04. Цена

- «Дешевле»/«Дороже» сортируют подходящую серверную выдачу, включая следующие страницы.
- Сортировка не должна превращать всю ленту в три записи только из-за того, что остальные без цены. Объявления без цены остаются доступны отдельной частью выдачи после записей с ценой.
- Разные валюты не сравниваются как одинаковые числа. Предусмотреть явный выбор валюты/понятные группы; при невозможности выбранного режима показать объяснение, а не молча выдавать другой порядок.
- «Договорная» и «Цена не указана» различаются. Ноль не подставляется вместо неизвестной цены.
- Для одинаковой цены — устойчивый дополнительный порядок по ID/времени, без пропусков и повторов при пагинации.

### FEED-FILTER-05. Комбинации

Все условия работают совместно, их применение видно в верхних кнопках. Изменение одного не стирает остальные. Пустая выдача объясняет наличие активных условий и даёт понятный способ очистки. Настоящая сетевая ошибка не выдаётся за отсутствие объявлений.

## 10. Карточка, раскрытие, закладки и нижнее меню

### FEED-UI-01. Карточка

Утверждённые цвета, размеры и общая структура сохраняются. Есть маршрут/местонахождение или честное обозначение «Направление в тексте», доступные параметры, цена/договорная/не указана, контакты, дата источника, полный текст, закладка и действия.

«Показать полностью»/«Свернуть» работают многократно. Фоновое обновление не закрывает раскрытую карточку, не обрезает номер и не переставляет пользователя в начало. Большой текст доступен прокруткой до последнего символа.

### FEED-UI-02. Закладки

Сохранение и удаление отражают подтверждённое серверное состояние; повторный тап не вызывает гонку. После перезапуска закладка сохраняется. В разделе сохранённых нет бесконечного спиннера. Отмена сохранения не стирает само объявление. Ошибка связи видима и допускает повтор.

### FEED-UI-03. Нижнее меню

У водителя основная лента грузов соответствует вкладке «Грузы», у грузоотправителя поиск транспорта — вкладке «Машины». Выбранная вкладка выделяется согласованным активным состоянием и не меняется от открытия клавиатуры/фильтра.

Внешняя лента сейчас отдельный экран со стрелкой назад. Назад должен возвращать в нужную вкладку с правильным выделением. Наличие/отсутствие нижнего бара на этом отдельном экране не менять случайно при исправлении модального окна.

Выделение варианта в нижнем окне фильтра и выделение вкладки нижней навигации проверяются отдельно.

## 11. Счётчики и типы записей

### FEED-COUNT-01. Честное значение

Счётчик — фактическое количество доступных пользователю объявлений данного типа на данном сервере. Справочник контактов перевозчиков показывается отдельно от числа свежих предложений машин.

Отдельно учитывать исходные посты, карточки после разбиения и число машин, заявленных внутри поста. «Нужно 10 машин» не создаёт десять одинаковых объявлений ради цифры.

Нельзя устанавливать искусственное значение 10 000, подменять машины грузами или прибавлять неподтверждённую доступность перевозчиков. Максимальное наполнение достигается исправным сбором и показом реальных исходников.

### FEED-COUNT-02. Совпадение устройств

Huawei, Xiaomi и iPhone при одинаковых сервере, роли, фильтрах и времени получают сопоставимые данные. В отчёте всегда указывать эти четыре условия. Разные режимы «Грузы»/«Машины» не должны обещать одинаковый счётчик.

В UI доступна диагностическая информация версии/сборки и окружения в подходящем служебном месте; пользователю не приходится определять сервер по косвенной разнице чисел.

## 12. Обновление, пагинация и устойчивость

### FEED-LIVE-01. Живой поток

Цель: UI проверяет изменения примерно каждые 2 секунды в активной открытой ленте. От получения нового поста сборщиком до доступности карточки — целевой p95 не более 10 секунд при исправных источнике/сервере; фактическое значение измеряется отдельно от частоты UI polling.

Отсутствие нового поста не компенсируется созданием искусственных карточек. Свежие сообщения не должны ждать завершения исторической очереди.

### FEED-LIVE-02. Прокрутка

Следующие страницы подгружаются без повторов/пропусков. Нет скрытого лимита на первые 30/100 карточек. Новые объявления не отрывают читающего пользователя от текущего места; при необходимости появляется кнопка новых объявлений. Раскрытый пост и положение его конца остаются стабильными.

### FEED-LIVE-03. Возврат и ошибки

После фона, блокировки, потери сети и перезапуска выполняется повторная синхронизация. Не показывать устаревшую роль или выдачу другого аккаунта. Загруженные записи не исчезают при одном неудачном запросе. Есть конечный timeout, понятная ошибка и повтор; запросы отменяются при смене фильтра/выходе с экрана.

Цель отклика: закрытие окна немедленно; первые результаты обычного фильтра — p95 до 2 секунд на рабочей сети, серверная часть измеряется отдельно. Непрерывный бесконечный спиннер не является допустимым состоянием.

## 13. Сроки публикации и восстановление

Собственные «Мои грузы» и «Мои рейсы/машины»: ранее согласованные 30 дней с момента публикации. Внешняя Telegram-лента имеет отдельную политику; текущий контракт 7 дней не подменяется сроком собственных публикаций.

Восстановление текста/контактов не продлевает дату источника и не возвращает закрытое автором объявление в активные. Если меняется срок внешней ленты, это отдельная явно описанная настройка с новым расчётом счётчика.

Восстановление существующих карточек: read-only план → резервная копия → обновление по существующей identity → проверка ACK и чтение результата → полный итоговый аудит. Естественное истечение срока во время запуска учитывается как отдельный ожидаемый исход, а не теряется в общем сообщении об ошибке.

## 14. Серверный контроль и отчётность

Для каждого источника и каждого потока отдельно показывать: получено, разобрано, опубликовано впервые, обновлено, точных дублей, закрыто источником, истекло, ожидает доставки, ошибка. Для контактов — отдельные причины отсутствия/неопределённости и связь с source ID/message ID.

Нужен отчёт за сегодня и последние три дня, с указанием часового пояса и границ периода. Не смешивать число Telegram-постов, сегментов, повторных доставок и активных карточек.

У очереди есть последние успешные получения/доставки, глубина и возраст старейшего необработанного сообщения. Ошибка одной записи не останавливает исправные соседние записи. Повторная доставка идемпотентна; очереди QA2/production и режимов источников не переиспользуются случайно.

Секреты, токены и полные личные данные не включаются в общедоступные CI-логи. Точные номера и исходники для диагностики доступны в приватном журнале и самом разрешённом объявлении.

## 15. Модули реализации и ограничения изменений

- Collector: `ops/telegram-feed/feed.py`, реестр источников.
- Разбор: `external_freight_parser.py`, `external_freight_classifier.py`, `owned_telegram_feed.py`.
- Доставка: `external_freight_queue_bridge.py`, `external_freight_import_adapter.py`.
- Контракт/хранение: `backend/api/external_freight.py`, `backend/database/external_freight_dal.py`.
- UI: `ExternalFreightFeedScreen.js`, `ExternalFeedDescription.js`, модели/клиент API и компоненты контактов/закладки.
- Навигация/локализация — только необходимая связка и подписи, без общего переписывания приложения.

Перед изменениями в gated-модулях — Graphify AST и анализ зависимостей по правилам проекта. Один дефект — отдельный минимальный патч и его проверки. Чат, сделки, GPS, документы, auth и платежи защищены от несвязанных изменений.

Серверная правка может дойти до старых совместимых клиентов без APK. Изменение UI фильтра не объявлять установленным в native-приложение после одного серверного deploy: требуется совместимая доставка JS или новая проверенная сборка. Web-проверка не заменяет native-проверку Huawei.

## 16. Порядок работ

1. **P0 — контакты:** классифицировать полный аудит, закрыть 484 подтверждённых разрыва, проверить все остальные пустые контакты и отсутствующие локальные исходники.
2. **P0 — зависание фильтров:** воспроизвести пустое поле/клавиатуру/переход к другому фильтру на Huawei; исправить закрытие и раздельный сброс.
3. **P0 — правильный тип/счётчик:** исключить смешение ролей, выделить справочник перевозчиков и фактические предложения машин.
4. **P1 — источники:** подтвердить фактическое включение собственного Telegram-чата и целостную доставку каждого его объявления.
5. **P1 — отдельный поиск машин:** включить независимый поток, словарь намерений и его метрики без остановки грузов.
6. **P1 — все фильтры/закладки/пагинация:** пройти матрицу ниже на одной согласованной сборке.
7. **P1 — живой поток:** измерить задержку и устойчивость обновления, повторной обработки и восстановления.
8. **Релиз:** все обязательные проверки, QA2, физический Huawei, затем доступные Xiaomi/iPhone; отчёт по конкретным сборкам.

Сначала закрываются контакты и блокирующее окно; добавление объёма само по себе не закрывает эти дефекты.

## 17. Данные и доказательства для проверки

Автотесты используют изолированные синтетические данные. В живую ленту не добавляются выдуманные грузы/машины для повышения счётчика или проверки.

Для физической проверки подобрать реальные объявления: один маршрут/один номер; несколько маршрутов/общий номер; разные локальные номера; телефон в середине; короткий номер; телефон перед Telegram/WhatsApp; длинная подборка; нет цены; нет разобранного маршрута; изменённый пост; источник без локальной копии.

Каждый дефект фиксируется с source/message/item ID, parser revision, API host, ролью, версией приложения и шагами воспроизведения. Для UI нужны снимки до/после и фактическое состояние фильтров, клавиатуры и выделений.

## 18. Устройства и организация прогона

Huawei — обязательный основной native-прогон: доступен сейчас. Полностью пройти обе роли/ленты с предусмотренным безопасным тестовым аккаунтом, не меняя роль рабочего аккаунта без необходимости.

Xiaomi — дополнительная проверка после основного Huawei; не является блокером для начала работы. Доступность проверена, но его интерфейс пока не трогался.

iPhone — отдельная проверка исправленного окна с клавиатурой, раскрытия/скролла, контактов и совместимости TestFlight. Android PASS не переносится на iOS.

До каждого прогона записать пакет, build, SHA, API host и роль. В конце оставлять владельцу понятный экран для проверки, с конкретным объявлением и выполненными шагами.

| A33 | Сравнение устройств при одинаковых условиях | Сопоставимые данные и объяснимый счётчик |
| A34 | Контакт справочника перевозчиков | Не выдаётся за подтверждённо свободную машину |
| A35 | Собственные публикации и внешние источники | Применяются разные согласованные сроки |
| A36 | Полный повторный аудит контактов/текста | Все остатки объяснены; необъяснённых потерь 0 |

## 20. Критерии завершения

Работа принимается только при одновременном выполнении:

- Закрыты P0 по контактам и зависанию окна, пройдены все применимые сценарии A01–A36.
- Есть итоговый полный аудит обоих типов, а не только несколько удобных карточек.
- Для остающихся пустых контактов есть проверенная причина; номер, присутствующий в доступном источнике, не скрыт.
- Подтверждено фактическое получение и доставка из собственного согласованного Telegram-чата.
- Отдельный поток машин работает параллельно; типы и счётчики не подменяются справочником/грузами.
- Результаты backend/frontend/E2E и физического Huawei привязаны к одному кандидату; iOS и Xiaomi имеют собственные статусы.
- Есть версия/пакет/SHA/host/роль, снимки, план отката и итог «PASS / PARTIAL / BLOCKED» по каждому блоку.

Фразы «код написан», «сервер отвечает», «на одном объявлении номер есть» и «счётчик вырос» по отдельности не закрывают это ТЗ.
