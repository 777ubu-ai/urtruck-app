# Повтор публикации после потери ответа

Клиент сохраняет `client_id`, владельца и точное тело первого запроса вместе с черновиком до POST. Груз и рейс используют существующие маршруты создания. После перезапуска неизменённая форма отправляет прежнее тело, включая ранее загруженные ключи фото.

Серверная добавочная таблица `marketplace_publication_operations` имеет ключ `(owner_user_id, client_id)`. Проверка роли предшествует поиску операции. Объявление и результат записываются одной SQLite-транзакцией под `BEGIN IMMEDIATE`. Повтор возвращает первоначальный `{ok,id}`. Изменённое содержимое или другой вид объявления с тем же ключом возвращает 409 `PUBLICATION_IDEMPOTENCY_CONFLICT` с результатом только этого владельца. Интерфейс предлагает открыть исходное объявление либо явно начать новую операцию, сохранив поля. Старые клиенты без `client_id` сохраняют прежний контракт.

Поколение черновика защищает новую форму от позднего ответа и автосохранения старого экземпляра. Смена аккаунта не переносит ключ или поля другому владельцу. Незавершённый исход POST автоматически не получает новый ключ.

Регрессии: настоящий API/SQLite, конкурентные запросы, rollback при ошибке записи результата, неправильная роль, другой владелец, изменённый запрос, старый клиент; реальные hook/component проверки. `publication-lost-response.spec.js` пропускает POST в изолированный настоящий сервер, обрывает его успешный ответ, перезапускает приложение и проверяет один результат для груза и рейса. Этот тест отдельно включён в CI с новой тестовой БД и процессом, без изменения OTP-лимитов.

QA2 развёртывается отдельно от production. До изменения: штатный online SQLite backup, проверка SHA/quick_check, восстановление и миграция копии, сверка исходных расходов по ID. При отказе вернуть сохранённые модули и прежний процесс на8002. Добавочная таблица совместима со старым кодом; действующую БД с новыми записями не заменять старым snapshot. Восстановление snapshot допустимо при подтверждённом повреждении до возобновления трафика, после сохранения повреждённой копии.

QA2 Android использует явный `api_environment=qa2` только в Internal testing, прежние package и upload key. Встроенные API/package/flavor/source SHA проверяются до загрузки. Production-проверка остаётся строгой. iOS собирается локально для внутренних TestFlight-тестеров. Этот документ не является разрешением публичного выпуска.

Push подписчикам вызывается после commit только при первом создании. Защита повторной публикации не является гарантией доставки push при остановке процесса между commit и уведомлением.
