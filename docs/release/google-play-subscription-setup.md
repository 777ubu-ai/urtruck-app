## Механика лимитов (актуальный канон)

- Без подписки: `FREE_CONTACT_LIMIT=3` раскрытия контакта в календарный месяц.
- С подпиской: `PREMIUM_CONTACT_LIMIT=30` (**предварительно, до решения
  начальства**; `0` = безлимит, но безлимит как продуктовая позиция отклонён).
- Экран подписки рисует «Контактов открыто: {used} из {limit}» при конечном
  лимите и «Безлимитный доступ» только при `limit=null` (`PREMIUM=0`) —
  текст в приложении менять не нужно, он следует за конфигом бэкенда.

## Спецпредложения (триал) — ПОКА ПРОПУСТИТЬ

**Не добавлять пробный период на текущем коде.** `SubscriptionScreen`
([src/screens/SubscriptionScreen.js:142](../../src/screens/SubscriptionScreen.js#L142))
берёт `subscriptionOfferDetails[0]?.offerToken` — первый оффер из каталога.
Пока базовый план один, это однозначно. С появлением триала Play возвращает
несколько офферов, порядок в массиве не гарантирован, и в покупку может уйти
не тот оффер (платный вместо триала или наоборот).

Порядок действий: запустить подписку с одним базовым планом → в коде сделать
явный выбор оффера (по `basePlanId` и/или по `pricingPhases` с нулевой ценой
для триала) → только после этого заводить оффер «7 дней бесплатно» для новых
клиентов.

## Чек-лист после активации (иначе покупки не заработают)

1. **Service account** в GCP + приглашение в Play Console с правом
   «Просмотр финансовых данных» → JSON-ключ в серверный
   `.env` как `GOOGLE_PLAY_SERVICE_ACCOUNT_JSON` (тот же ключ, что в секрете
   GitHub `PLAY_SERVICE_ACCOUNT_JSON`). Пусто = MOCK-режим, только dev.
2. **RTDN**: Монетизация → Настройка → Уведомления разработчика в реальном
   времени → топик Pub/Sub → push-подписка на
   `POST /api/v1/payments/google/rtdn`.
3. **License testers** — Настройки → Лицензионное тестирование: покупают без
   списания (подписка протухает за ~30 минут, удобно для проверки
   отмены/протухания).
4. **Privacy policy** — дописать пункт про покупки внутри приложения, Google
   это проверяет при ревью.
5. `PREMIUM_CONTACT_LIMIT=30` на сервере (см. `.env.example:180`).
6. `CONTACTS_MONETIZATION_ENABLED=true` — **только по согласованию с
   владельцем** (сейчас `false`, `IS_BETA=true`, контакты бесплатны).
7. Сборка с `com.android.vending.BILLING` (versionCode 211006331) опубликована
   в internal-треке 08.09.2026 — условие для покупок выполнено. Прод-трек
   получит подписку только после merge `payments` → `main`.
