# UrTruck — Чат и Push: техническое описание

Документ для команды разработки: что уже реализовано в чате и push-уведомлениях,
как это работает, какие эндпоинты и таблицы, и что осталось доработать.

Стек: **Frontend** — React Native + Expo (SDK 52), деплой в web/PWA (urtruck.kz).
**Backend** — FastAPI (Python 3.12) + SQLite, сервер 185.22.65.11, PM2 `urtruck-security-api`.
API-префикс: `/api/v1/...`. Вся переписка хранится **на сервере** (SQLite), не на устройстве.

---

## 1. Архитектура чата

- Чат **привязан к заказу (сделке)**, а не к человеку. Ключ комнаты канонический:
  - `c:{cargo_id}:{p1}:{p2}` — чат по грузу;
  - `t:{trip_id}:{p1}:{p2}` — чат по рейсу;
  - `p:{p1}:{p2}` — общий чат/поддержка (без сделки).
  - `p1,p2` — отсортированная пара участников.
- Один водитель ↔ один клиент по **разным грузам = разные чаты** (не смешиваются).
- Таблицы: `chat_rooms` (participant_1/2, owner_id, bidder_id, cargo_id, trip_id, deal_key,
  last_message, last_at) и `chat_messages` (room_id, sender_id, text, photo_url, is_voice,
  voice_duration, client_msg_id, is_read, created_at).

## 2. Сообщения — что работает

| Тип | Статус | Как |
|---|---|---|
| **Текст** | ✅ | Оптимистичная отправка + идемпотентность по `client_msg_id`; офлайн-очередь (outbox) досылает при возврате сети |
| **Фото** | ✅ | Камера или Галерея → сжатие → upload в storage (`/chat/photo`) → ключ → сообщение с подписанным URL (видно обеим сторонам) |
| **Документы** | ✅ | Отдельная секция вложений сделки (PDF/фото): статусы queued/uploading/uploaded/failed/retry, ретрай без дублей |
| **Голосовые** | ⛔ выключены | Код записи есть, но **аудиофайл не выгружается на сервер** → получатель звук не получит. Кнопка скрыта до реализации upload аудио |
| **Автоперевод** | ✅ | Перевод отдельного сообщения по кнопке 🌐 + режим «переводить всю ленту» на язык интерфейса. 4 языка: RU/KK/ZH/EN |
| **Быстрые фразы** | ✅ | Пресеты **по роли**: водитель (Статус/Груз/Оплата/Документы), клиент (Где машина/Документы/Оплата) |

## 3. Комната сделки (Deal Room) внутри чата

- **Шапка чата**: имя собеседника + роль + **📦 груз · Откуда → Куда** (сразу видно, по какому заказу).
- **Карточка сделки**: маршрут, груз, цена/валюта, госномер.
- **Статус-таймлайн**: 🤝 Принят → 🚛 В пути → 🛂 На границе → ✅ Доставлен (пройдено зелёным, текущий подсвечен).
- **Кнопка 📞 «Позвонить»**: набирает **реальный номер** собеседника (`tel:`), появляется при активной сделке. Видео/VoIP-звонков **нет** (см. §8).
- **«Где машина»**: карта с живой геопозицией водителя (км до места, скорость, ETA, «на границе»); водитель транслирует позицию автоматически, пока приложение открыто (после разового разрешения на локацию).

## 4. Прочтение и счётчики

- `chat_messages.is_read` — входящие помечаются прочитанными при открытии комнаты.
- Непрочитанные: бейдж на вкладке «Чаты» + **красный кружок на иконке приложения** (app badge).
- Отправитель видит галочку ✓ (отправлено). Отдельного «прочитано у собеседника» отправителю сейчас нет.

## 5. Безопасность / доступ

- Все эндпоинты чата проверяют **участие**: не-участник получает 403.
- Телефон собеседника отдаётся только участнику сделки, технические placeholder-номера (guest_/deleted_) не отдаются.

## 6. PUSH-уведомления

### Каналы
- **Native (iOS/Android)** — Expo Push / APNs. Токен `ExponentPushToken`, таблица `push_tokens_native`.
- **Web/PWA** — Web Push (VAPID), Service Worker, таблица `push_subscriptions`.
- Токен **привязывается к user_id** при регистрации; если пользователь залогинен, но привязка не удалась (протух токен) — клиент повторяет регистрацию (иначе адресный пуш не дойдёт).

### Что присылает push (события)
| Событие | Кому | Текст (пример) |
|---|---|---|
| Новое сообщение в чате | собеседнику | имя + текст/«📷 Фото» |
| Ставка принята | водителю | «✅ Ставка принята» + сумма в валюте |
| Ставка отклонена | водителю | «❌ Ставка отклонена» + сумма |
| Контр-оффер / скидка | второй стороне | сумма в валюте |
| Смена статуса сделки | второй стороне | 🚛 В пути / 🛂 На границе / ✅ Доставлен / ❌ Отменено |
| Очередь на границе подошла | водителю (watch по ГРНЗ) | «🚛 Ваша очередь подошла» |
| Срок публикации истёк | владельцу | «⏳ Продлить?» |
| Напоминания (неактивным / по сохранённым маршрутам) | пользователю | «Есть новые грузы» |

- **Дедуп**: `push_log` (kind + время) — один и тот же пуш не задваивается.
- **Колокольчик**: параллельно с push пишется in-app уведомление (таблица уведомлений) — история в «Колокольчике».
- **Deep-link**: тап по пушу открывает нужный экран (сделку `/deals/{id}`, чат, груз/рейс), а не просто главную.
- **Suppress**: если ты уже открыл комнату X и пришло сообщение в X — баннер не показывается (native). На web пока показывается (доработать).
- Валюта в текстах — реальная (KZT/RUB/CNY/USD), не хардкод `$`.

## 7. Эндпоинты (для программистов)

**Чат** (`/api/v1/chat`):
- `POST /send` — отправка (text / photo_url / is_voice+voice_duration; room_id или to_user_id; client_msg_id для идемпотентности; lang)
- `GET /rooms` — список чатов (+ маршрут, груз, deal_id, deal_status, unread, партнёр)
- `GET /messages/{room_id}` — сообщения комнаты (помечает входящие прочитанными)
- `GET /contacts` — контакты
- `GET /unread` — счётчик непрочитанных
- `POST /photo` — загрузка фото чата → ключ
- `GET /translate/info`, `POST /translate` — перевод

**Push** (`/api/v1/push`):
- `GET /public-key` — VAPID для web
- `GET /info` — режим (mock/real)
- `POST /subscribe` / `POST /unsubscribe` — web-подписка (возвращает user_id)
- `POST /register-native` / `POST /unregister-native` — Expo-токен
- `POST /test` — тестовый пуш (только себе)

## 8. Чего пока НЕТ / доработать (задачи для команды)

1. **Голосовые сообщения** — реализовать upload аудио (по аналогии с фото: storage → подписанный URL), затем включить кнопку 🎤. Сейчас выключены.
2. **Видео/аудио-звонки внутри приложения (VoIP, как в WhatsApp)** — не реализованы. Нужен WebRTC + сигналинг + TURN/STUN + провайдер (Agora/Twilio/Daily), платно. Сейчас только `tel:`-звонок на реальный номер.
3. **Фоновый GPS-трекинг** (когда приложение закрыто) — не реализован. Сейчас позиция водителя шлётся только пока приложение открыто. Нужен expo-task-manager + разрешение «Всегда» + обоснование для App Store.
4. **«Прочитано» отправителю** (двойная галочка/read receipt как в WhatsApp) — есть только is_read для счётчиков, отправителю статус прочтения не показывается.
5. **Индикатор «печатает…»** — нет.
6. **Редактирование / удаление сообщений** — нет.
7. **Suppress баннера на web** в открытой комнате — доработать (на native работает).
8. **Групповые чаты** — нет (только 1:1 по сделке). Для UrTruck сейчас и не требуется.

## 9. Что недавно исправлено (уже сделано)
- Фото/голос уходят в правильную комнату сделки (не в отдельную).
- Web-push привязка к user_id (не терялся адресный пуш).
- Кнопка звонка/маршрут/карточка сделки подгружаются при входе из «Чаты» (не только по deep-link).
- Трекинг не замерзает на статусе «На границе».
- Быстрые фразы разделены по ролям.
- Валюта в push-текстах вместо `$`.

---
*Замечание по тестированию:* пуши, камера, GPS-трекинг и звонок проверяются только на **реальном устройстве** (не в web/симуляторе). Веб-версия (urtruck.kz) покрывает текст/фото/перевод/UI.
