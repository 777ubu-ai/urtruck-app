# ПРОМ для терминал-агента (Claude Code + Maestro на Mac) — ГЛУБОКИЙ тест роли ГРУЗООТПРАВИТЕЛЯ (client)

> Скопируй ВСЁ ниже (от «=== НАЧАЛО ПРОМА ===») в терминальный Claude Code на Mac.
> Он привязан к Maestro + iOS-симулятору — реально нажимает и смотрит.
> Это **специальный прогон только по роли client (грузоотправитель/shipper)** —
> владелец говорит, что там «красота полная жопа» и логику толком не смотрели.
> Driver не трогаем: его канон (5 вкладок Feed/MyWork/Queue/Chats/Profile) — нерушим.

=== НАЧАЛО ПРОМА ===

РОЛЬ: ты — придирчивый QA-инженер с Maestro и iOS-симулятором. Задача — НЕ написать
тесты ради тестов, а **реально пройти приложение UrTruck глазами ГРУЗООТПРАВИТЕЛЯ
(client), нажать каждую кнопку, проверить логику бизнес-цикла груза и найти, где
ломается логика и где «некрасиво»**. Работай автономно, разрешений на чтение/запуск
Maestro не спрашивай.

ЯЗЫК: общение и отчёт — по-русски.

ПОЧЕМУ ЭТО ВАЖНО (бизнес-логика владельца): нет доверия грузоотправителя → он не
публикует груз → водителю нечего возить. Поэтому роль client должна выглядеть и
работать «мощно»: премиально, без мёртвых кнопок, без водительских артефактов в
профиле, с понятным циклом «опубликовал → выбрал водителя → вижу, где едет →
получил → оценил».

ПРАВИЛА (жёстко):
- Тестируем ТОЛЬКО client. Driver — лишь для сверки, что мы ему ничего не сломали.
- НЕ менять навигационный канон driver (5 вкладок). Клиентский бар СЕЙЧАС — 5 вкладок:
  **MyWork / Feed / Publish / Chats / Profile** (Chats добавлен недавно; Queue у
  клиента НЕ должно быть).
- НЕ трогать секреты/ключи (Supabase anon-key, .env).
- Найденные баги: P0/P1 — чинить сразу на текущей ветке маленькими коммитами; P2 —
  в отчёт. НЕ мержить PR, НЕ запускать `eas build`, НЕ менять buildNumber/version/icon.
- На каждый значимый шаг — `takeScreenshot`. К каждому багу: экран, что нажал, что
  ожидал, что получил, severity, и file:line причины (найди в коде).

ОКРУЖЕНИЕ (подними сам):
1. Expo Go в симуляторе: `npx expo start --ios` (если Expo Go снесён — переустанови).
2. Локальный backend (НЕ прод):
   `cd backend && export URTRUCK_ENV=development && export QA_AGENT_TOKEN="$(openssl rand -hex 32)"`
   `DB_PATH="$PWD/database/security.db" python -m uvicorn main:app --host 0.0.0.0 --port 8001 &`
3. Прокинь в Maestro: `export MAESTRO_QA_AGENT_TOKEN="$QA_AGENT_TOKEN"` и
   `export MAESTRO_BACKEND_BASE="http://127.0.0.1:8001/api/v1"`.
4. QA-логин: `qa/maestro/_lib/qa-login.yaml`. Актёр клиента — **boris** (`MAESTRO_ACTOR=boris`).
   Для проверки сделок понадобится и driver-актёр **serik** (он ставит ставку на твой
   груз, чтобы ты как client мог выбрать водителя). Готовые client-флоу:
   `client-auth.yaml`, `client-tabs.yaml`, `createcargo-authenticated.yaml`.
5. appId Expo Go = `host.exp.Exponent`.

CA3. Нет лишних/мёртвых вкладок; тап по каждой вкладке открывает свой экран без краша.

CB. ПУБЛИКАЦИЯ ГРУЗА (Publish → CreateCargo) — главный вход доверия
CB1. Тап `bottom-nav-publish` открывает форму CreateCargo (а не пустой stub).
CB2. Введи описание (`cargo-desc-input`), раскрой маршрут, заполни откуда/куда

CB3. `cargo-submit-button`: публикация проходит, появляется тост/переход, груз
     появляется в MyWork → «Мои грузы». Если сети нет — внятная ошибка, не молчит.
CB4. Валидация: пустая форма не публикуется молча; обязательные поля подсвечены.
CB5. Загрузка фото груза (если есть): «Файл слишком большой» НЕ должно вылетать

CC. MYWORK КЛИЕНТА — 3 вкладки + архив (зеркало водителя)
CC1. Вкладки читаются целиком: «Мои грузы» / «Везут» / «Доставлено» + «Архив (N)».
     Не обрезаны («Доставле…»), не сырые ключи `client_tab_*`.
CC2. «Мои грузы» (`my-work-tab-searching`) показывает ТОЛЬКО активные/ищущие грузы
     (status null|'active'), НЕ доставленные, НЕ отменённые.
CC3. «Везут» (`my-work-tab-enroute`) показывает ТОЛЬКО сделки в перевозке
     (status accepted/in-progress). Тут есть кнопка `deal-track-truck`.
CC4. «Доставлено» (`my-work-tab-delivered`) — только завершённые.
CC5. «Архив» — отменённые/истёкшие/отклонённые, БЕЗ активных. Счётчик (N) совпадает
     с числом карточек внутри.
CC6. Счётчики/бейджи на вкладках совпадают с реальным содержимым (старый баг: «34
     Ставок» не совпадал ни с одной вкладкой). Если где-то цифра не сходится — FAIL.

CD. УПРАВЛЕНИЕ СВОИМ ГРУЗОМ (задача A)

CE. ВЫБОР ВОДИТЕЛЯ ПО СТАВКАМ (ключевая стадия — «выбираю водителя»)
