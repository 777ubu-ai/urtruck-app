# ТЕРМИНАЛ-БРИФ: сквозная проверка торга через Maestro + QA → сразу билд

**Ветка:** `claude/youthful-cerf-barf3`
**Режим:** непрерывный. Проверил → зелёно → СРАЗУ запускаешь билд. Без пауз на подтверждение.
**Язык отчёта:** русский.

---

## 0. Что именно проверяем (контекст, не пропускать)

В этой ветке переделана **самая главная страница — торг** (решение владельца
01.08: «от этой страницы зависит, как клиент торгуется и покупает»). Обе роли
теперь торгуются симметрично, как на рынке. Твоя задача — пройти это ЖИВЬЁМ на
симуляторе через Maestro + прогнать API-логику через Playwright-QA, и на зелёном
сразу собрать билд.

Что изменилось (это и есть фокус проверки):
1. **TripDetail (клиент смотрит машину):**
   - Встречная цена водителя видна клиенту суммой + [Отклонить] [Чат] [Принять $X].
   - Экран живой: обновление при фокусе + поллинг 15с (не «замерзает»).
   - Карточка водителя: имя, ✅ верификация, ⭐ рейтинг, тап → профиль.
   - Счётчик «N предложений», чат ДО ставки, быстрые чипы торгуются ВНИЗ.
   - Владелец рейса видит ставки клиентов: [Отклонить][Встречка][Чат][Принять].
   - Таймлайн сделки + блок отзыва после «Доставлено».
2. **CargoDetail (водитель смотрит груз):**
   - Своя ставка НЕ дублируется: только в плашке «МОЯ СТАВКА», не в списке.
   - Плашка: pending [Изменить][Чат][Отменить]; countered — встречка клиента
     суммой + [Отклонить][Чат][Принять $X].
3. **BidModal:** нет duplicate_bid сырым кодом; чипы направленные.
4. **Web/PWA:** убрана синяя браузерная рамка фокуса (outline) везде.
5. **Backend:** `get_trip` отдаёт driver_rating/verified/reviews;
   `my_dashboard.incoming_bids` включает ставки на рейсы.

## 2. Фаза A — Playwright QA (логика торга, стыки с сервером)

Это ловит то, что Maestro не видит (ответы сервера, история цены, приватность).
Запускай по одному, фиксируй PASS/FAIL:

```bash
npm run qa:bargain        # ⭐ ГЛАВНОЕ: сквозной торг proposed→countered→accepted
npm run qa:serik          # водитель: ставки, встречки, чат
npm run qa:boris          # грузоотправитель: приём/отклонение/контр
npm run qa:auditor        # приватность: чужой не читает историю цены (403), нет утечки телефона
npm run qa:trip-details   # клики по TripDetail
npm run qa:full           # полный прогон
```

**Критерий торга (qa:bargain обязан пройти целиком):**
boris публикует груз → serik ставит → boris контр → serik принимает →
создаётся сделка → `/bids/{id}/events` = proposed→countered→accepted →
auditor получает 403 на историю → телефон оферента НЕ утекает не-владельцу.

## 3. Фаза B — Maestro (живьём, каждая страница глазами)

Прогони все флоу и СМОТРИ каждый экран (скриншоты Maestro сохраняет сам):

```bash
maestro test .maestro/11-smoke-all-tabs.yaml     # все вкладки обеих ролей открываются
maestro test .maestro/07-chat-shipper.yaml        # переписка со стороны клиента
maestro test .maestro/08-chat-driver.yaml         # переписка со стороны водителя
maestro test .maestro/12-push-deeplink-bid.yaml    # пуш о ставке → правильный экран
maestro test .maestro/13-push-badge-sync.yaml      # бейдж непрочитанного
maestro test .maestro/04-driver-no-cta.yaml
maestro test .maestro/05-marketplace-preserved.yaml
# и остальные .maestro/*.yaml по списку
```

**Ручные глаза-чек по торгу (пройти обеими ролями, driver ↔ shipper):**
- [ ] Клиент открывает рейс → «Предложить цену» → ставка ушла, появилась плашка
      «МОЯ СТАВКА» с суммой (НЕ «холодный» пустой экран).
- [ ] Водитель на этом рейсе видит ставку клиента → жмёт «Встречка» → вводит цену.
- [ ] Клиент видит встречку СУММОЙ + [Отклонить][Чат][Принять $X] → «Принять» →
      создаётся сделка, появляется таймлайн.
- [ ] Водитель на чужом грузе: своя ставка показана ОДИН раз (плашка «МОЯ
      СТАВКА»), НЕ продублирована в списке предложений.
- [ ] Клиент даёт встречку по грузу → водитель принимает из плашки «МОЯ СТАВКА».
- [ ] Счётчик «N предложений» виден обеим ролям.
- [ ] Чат открывается и ДО ставки (кнопка на нижней панели).
- [ ] После «Доставлено» — блок отзыва (звёзды) у обеих ролей.
- [ ] Web/PWA: при вводе цены НЕТ синей браузерной рамки поверх поля.
- [ ] Переписка driver↔shipper: сообщение уходит и приходит, бейдж гаснет в «Сделках».

## 4. Фаза C — на зелёном СРАЗУ билд (без остановки)

Если Фаза A и Фаза B **полностью зелёные** (нет P0/P1) — НЕ жди подтверждения,
сразу запускай сборку следующего билда:

- **Android APK** уже собирается автоматически на push в `claude/**`
  (GitHub Actions «Build Android APK») — проверь, что последний прогон зелёный:
  зайди в Actions и дождись артефакта/релиза.
- **iOS/номерной билд** — запускай командой из привычного пресета:
  ```bash
  eas build --profile production --platform ios
  ```
  (или `--profile preview` для internal, как делали раньше — бери тот профиль,
  которым собирали прошлый номерной билд).

Инкремент `.version` и `./deploy.sh` (веб-прод) — только если владелец отдельно
скажет катить веб; сам по себе прогон QA веб не деплоит.
