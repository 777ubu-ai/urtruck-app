# ЗАДАЧА для Терминал-Клода (Mac): ПОЛНЫЙ регресс каждой кнопки обеих ролей через Maestro

**Цель:** пройти приложение НАСКВОЗЬ — каждый экран, КАЖДУЮ кнопку, обе роли —
и убедиться, что логика не падает, ошибок нет, всё работает чётко. Это большой
прогон на 2–3 часа (при нестабильности драйвера — на день). Не торопись.

## 🚫 ГЛАВНОЕ ПРАВИЛО
**НИЧЕГО НЕ СОБИРАТЬ. Забудь слова «build», «eas», «залить в стор».**
Никаких `eas build`, никаких новых buildNumber. Только прогон и фиксы.
Финальную сборку владелец закажет ОТДЕЛЬНО, когда весь регресс будет зелёным
и он лично подтвердит. До этого — только Maestro + код-фиксы.

## 0. Синхронизация
```
git fetch origin && git checkout claude/youthful-cerf-barf3 && git pull
npm install
npx expo prebuild -p ios --clean   # для натива; для web-прогона не обязателен
```
Актуальный код влит и в `main` (задеплоен на urtruck.kz). Тестируй ТОЛЬКО
актёрами `agent-boris` (client) и `agent-serik` (driver) через
`qa/maestro/_lib/qa-login.yaml`. **Реальных пользователей НЕ трогать.**
`app.json` version 1.0.2 НЕ менять. Хуки не пропускать. В `main` не форсить.

## Метод (для КАЖДОГО экрана)
Для каждой кнопки/поля проверяй по чек-листу:
1. **Видна и кликабельна** (не «мёртвая»).
2. **Делает что обещает** (открывает нужный экран/модалку/действие).
3. **Есть обратная связь** (тост/переход/изменение состояния).
4. **Назад/закрыть** возвращает корректно, без «замирания» и пустых экранов.
5. **Нет сырых i18n-ключей** (типа `truck_params_next`) и «—/undefined/NaN».
6. **Логика:** действие реально доходит до backend (проверь по сети/БД, где можно).
Каждый упавший шаг фиксируй: экран → кнопка → что ждали → что вышло + скриншот.

## ФАЗА 1 — ГРУЗООТПРАВИТЕЛЬ (client, actor agent-boris)
Прогоняй строго с первого экрана и по каждой вкладке слева направо.

### 1.1 Вход / первый экран
- qa-login под client → попадает в ленту. Сплэш/онбординг/авторизация без зависаний.

### 1.2 Вкладка «Грузы» (лента машин/рейсов)
- Селектор «Откуда → Куда»: тап «Откуда» → полноэкранный пикер; **тап по стране →
  раскрываются её города**; поиск города; выбор подставляется; «← Все страны»;
  крестик сбрасывает оба поля.
- Чипы-фильтры: Дата (календарь: сегодня/завтра/диапазон), Тип кузова, Цена
  (сортировка). Каждый открывает свою шторку, применяется, сбрасывается.
- Карточка рейса/водителя: маршрут, цена, вторая строка (дата/вес/объём/кузов),
  ❤️ (ровно ОДНА карточка меняется на тап, не две), «Подробнее» открывает деталь.
- Пул-ту-рефреш, бесконечный скролл, скролл жив после «карточка → назад».
- Колокольчик (уведомления) открывается; бейдж соответствует.

### 1.3 Вкладка «Машины»
- Открой, прогони все кнопки/фильтры, переходы в детали, назад.

### 1.4 Вкладка «Разместить» (создание груза)
- Откуда/Куда (пикер + страна→города), описание груза (автодополнение),
  тип кузова, дата загрузки (обязательна), вес/объём, сумма + валюта
  (**USD по умолчанию**), способ оплаты.
- Валидация: пустая цена/дата НЕ публикуются; «по договорённости» отсутствует.
- Публикация → тост успеха → груз появляется в «Мои грузы».

### 1.5 Вкладка «Чаты» / комната сделки
- Список чатов; вход в комнату сделки.
- Кнопка **«Позвонить»**: WhatsApp / Telegram / Звонок (Viber НЕТ), номер полный.
- Вложение: **«Прикрепить» / «Документ»** открывает выбор (галерея/файл/PDF);
  отправленное фото открывается **на весь экран по тапу** (C2).
- Голосовое: запись → отправка → воспроизведение (на симуляторе мик ограничен →
  минимум smoke; полный e2e — на 2 устройствах).
- Быстрые фразы по контексту роли; «печатает…»/«в сети»; геолокация.
- События сделки в ленте (Принято/Статус изменён) + переход по ним.

### 1.6 Вкладка «Профиль»
- Международный профиль: мессенджер (WeChat/WhatsApp/Telegram/Viber) + ID,
  БИН/ИНН, компания — сохранение и повторное открытие.
- «Избранное»: сохранённый перевозчик присутствует (не пусто); открытие
  карточки — без пустых прочерков, показывает что есть.
- «Как это работает» (по роли клиента), язык (4 языка переключаются),
  выход, версия 1.0.2.

## ФАЗА 2 — ВОДИТЕЛЬ (driver, actor agent-serik)
Канон таб-бара водителя: **Feed / MyWork / Queue / Chats / Profile** (5 вкладок).
Прогоняй так же — каждую кнопку.

### 2.1 Верификация водителя (КРИТИЧНО — свежая переделка)
- Гражданство → **Документ личности: тумблер удостоверение/паспорт → 2 стороны**
  → **Техпаспорт 2 стороны** → **Права 2 стороны** → Параметры фуры → submit.
- Личного фото / селфи с правами **НЕТ**. «Кандас» в статусе пребывания **НЕТ**
  (только гражданин Казахстана / иностранец). Прогресс «Шаг N из N» корректен.
- Повторный вход подтягивает загруженные стороны (не просит заново).
- submit не падает при пустых OCR-полях. Статус/тир после верификации
  (🟡 Новичок → 🔵 Проверенный → 🟢 Профи, шкала 50/80/100).
- Флоу: `verify-3docs-2sides.yaml` (есть) + `verify-reentry-prefill.yaml` (написать).

### 2.2 Feed (лента грузов)
- Фильтры маршрут/дата/тип/цена; карточка груза (маршрут/цена/дата/вес/объём/тип,
  км + ставка-за-км); «Подробнее»; «Откликнуться»/ставка; кол-во откликов.
- Подписка «🔔 грузы по маршруту» когда заданы обе точки.

### 2.3 MyWork («Мои рейсы»/ставки)
- Вкладки: Мои рейсы / Предложения / В работе / Завершённые; счётчики.
- По ставке (pending): Изменить / **Дать скидку** / Чат / Отмена.
  **Скидка на ПРИНЯТОЙ ставке — кнопка «Отправить» заблокирована** (не даёт
  жать повторно и ловить ошибку).
- Предел скидки −90% (нельзя ронять до $1).

### 2.4 Queue (очередь на границе)
- Открой, все кнопки; честный «Нет данных» вместо демо-цифр.

### 2.5 Chats
- То же, что 1.5, со стороны водителя (`marketplace-driver-chat`, `chat_driver_view`).

### 2.6 Profile
- Статус/тир/баллы видны сразу после верификации; бейджи; «Как это работает»
  (роль водителя); язык; выход; версия.

## ФАЗА 3 — СКВОЗНОЕ (обе роли)
- **Уведомления/пуши:** на КАЖДОЕ событие (новая ставка, смена статуса сделки,
  новое сообщение) — запись в колокольчике с понятным текстом «откуда» и
  переходом (deeplink) к нужному грузу/сделке/чату. Проверь bid→client и
  deal-events. Push-доставка — device-зависима (проверка на устройстве отдельно),
  но лента уведомлений и deeplink должны работать.
  Флоу: `chat_bid_notifications_e2e`, `deal_bell_price_e2e`,
  `.maestro/12-push-deeplink-bid`, `13-push-badge-sync`, `unread-badge-flow`.
- **Валюта:** везде `$` (карточки/ставки/уведомления/таймлайн), не ₸/EUR.
- **i18n:** переключение RU/KK/ZH/EN не ломает экраны; города/типы груза
  переводятся (Хоргос→霍尔果斯, Обувь→鞋类); нигде нет сырых ключей.
- **Навигация/таб-бары:** канон водителя (5 вкладок, Queue отдельная, Chat не в
  Profile); клиентский таб-бар не сломан; «замирания» ленты нет после переходов.

## Фиксы
Всё, что упало по логике/коду — чинить в тот же день (P0→P1→P2). Если фикс уходит
в архитектуру или зону вне текущих правок — сперва спросить владельца
(`AskUserQuestion`). После фиксов — перепрогнать упавшее. Коммить в ветку
`claude/youthful-cerf-barf3`, пушить ветку (в `main` не лезь — туда переносит
ассистент после ревью).

## Отчёт владельцу (структурой)
- Таблица: экран → кнопка → 🟢/🔴 → примечание.
- Отдельно: что упало и почему (первопричина), что починил, что осталось.
- Что можно проверить только на реальном устройстве (голос e2e, пуш на локскрин,
  камера/PDF, фоновый GPS) — вынеси списком.
- **Итог: сколько кнопок/флоу зелёных из общего числа. Пока не 100% по логике —
  НЕ предлагать сборку.**

Когда всё зелёное — отчёт ассистенту/владельцу. Сборку (build) закажет владелец
сам, отдельно, после этого. Часовые пояса, AI-матчинг, сервис-хаб, WeChat-контакт,
«грузы по пути» — вне объёма, это дорожная карта.
