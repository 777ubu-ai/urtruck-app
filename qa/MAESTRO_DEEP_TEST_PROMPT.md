# ПРОМ для терминал-агента (Claude Code + Maestro на Mac) — глубокий тест UrTruck

> Скопируй ВСЁ ниже (от «=== НАЧАЛО ПРОМА ===») в терминальный Claude Code на Mac.
> Он привязан к Maestro и iOS-симулятору — сможет реально нажимать и смотреть.

---

=== НАЧАЛО ПРОМА ===

РОЛЬ: ты — QA-инженер с доступом к Maestro и iOS-симулятору. Задача — НЕ написать
тесты ради тестов, а **реально пройти приложение UrTruck руками через Maestro,
нажать кнопки, проверить ЛОГИКУ и найти места, где она ломается** — отдельно для
водителя (driver) и для грузовладельца (client/shipper). Работай автономно, не
спрашивай разрешений на чтение/запуск Maestro.

ЯЗЫК: общение и отчёт — по-русски.

ПРАВИЛА (жёстко):
- НЕ ломать навигационный канон: driver tab-bar = 5 вкладок (Feed / MyWork / Queue /
  Chats / Profile); Chat — отдельная вкладка, не прятать в Profile; Queue — отдельная
  центральная вкладка; клиентский tab-bar не трогать.
- НЕ трогать секреты/ключи (Supabase anon-key, .env).
- Найденные баги: P0/P1 — чинить сразу на текущей ветке маленькими коммитами; P2 —
  записать в отчёт. НЕ мержить PR, НЕ запускать eas build.
- На каждый шаг — `takeScreenshot`. К каждому багу: экран, что нажал, что ожидал,
  что получил, severity, file:line причины (найди в коде).

ОКРУЖЕНИЕ (подними сам):
1. Expo Go мог быть удалён из симулятора — переустанови/запусти: `npx expo start --ios`.
2. Локальный backend (НЕ прод):
   `cd backend && export URTRUCK_ENV=development && export QA_AGENT_TOKEN="$(openssl rand -hex 32)"`
   `DB_PATH="$PWD/database/security.db" python -m uvicorn main:app --host 0.0.0.0 --port 8001 &`
3. Прокинь в Maestro: `export MAESTRO_QA_AGENT_TOKEN="$QA_AGENT_TOKEN"` и
   `export MAESTRO_BACKEND_BASE="http://127.0.0.1:8001/api/v1"`.
4. QA-логин: используй `qa/maestro/_lib/qa-login.yaml` (актёры: serik=driver, boris=client).
   Готовые флоу — в `qa/maestro/*.yaml`, новые — там же.
5. appId Expo Go = `host.exp.Exponent`. Для push-инъекции (если будешь): standalone
   `com.urtruck.app` + `xcrun simctl push` (см. `.maestro/10-foreground-push-suppress.yaml`).

═══════════════ ЧЕК-ЛИСТ ЛОГИКИ (проверь КАЖДЫЙ пункт, оба роли) ═══════════════

A. ОНБОРДИНГ/ВХОД
A1. Гость («Смотреть грузы»): если сети нет — НЕ должно кидать в пустой Main, а
    показать ошибку и остаться. С сетью — открывает ленту.
A2. После QA-логина driver видит РОВНО 5 вкладок; client — свой бар (Publish виден,
    Queue/Chats скрыты). Лишних/мёртвых вкладок нет.

B. ЛЕНТА ГРУЗОВ (driver)
B1. Карточка груза показывает ПОЛНЫЙ маршрут «город, страна → город, страна», пункт
    назначения НЕ обрезан многоточием.
B2. Поиск «Алматы→Москва» (со стрелкой) фильтрует; несуществующий «Нигде→Никуда» →
    пустое состояние без карточек «— → —»; очистка поиска возвращает ленту.
B3. Свои грузы НЕ показываются в чужой ленте.

C. КАРТОЧКА ГРУЗА + ЧАТ ДО СТАВКИ (ключевое!)
C1. Внизу карточки чужого груза ОБЯЗАНЫ быть ДВЕ кнопки: `cargo-sticky-bid`
    («Предложить цену») и `cargo-sticky-chat` («💬 Чат по заказу»).
C2. Тап по `cargo-sticky-chat` БЕЗ ставки → открывается чат с грузовладельцем
    (`chat-input` виден), приложение не падает. Это недавно чинили — проверь, что
    кнопка реально есть и работает.
C3. Заголовок чата — реальное имя/№, НЕ «Собеседник».

D. ЖИЗНЕННЫЙ ЦИКЛ СТАВКИ (логика денег — самое важное)
D1. Нельзя оставить ДВЕ свои активные ставки на один груз (вторая попытка → ошибка
    «У вас уже есть активная ставка»).
D2. Нельзя ставить на уже занятый/истёкший груз (→ «Груз больше не доступен»).
D3. Владелец: двойной быстрый тап «Принять» создаёт ТОЛЬКО ОДНУ сделку (второй →
    «уже обработана»), НЕ две.
D4. После отклонения ставки счётчик «N откликов» УМЕНЬШАЕТСЯ (не завышается).
D5. Контр-оффер: владелец отправил → водитель видит, может принять/отклонить;
    принятие создаёт сделку. Тексты пушей с правильной ролью.

E. MYWORK — DRIVER (4 вкладки + архив)
E1. Вкладки целиком читаются (не «Предложе…», «Завершён…»): «Мои рейсы /
    Предложения / В работе / Завершённые» + ссылка «Архив (N)».
E2. Принятая сделка («Начать перевозку») — в «В работе», НЕ в «Архиве». В Архиве
    только отменённые/отклонённые/истёкшие, БЕЗ кнопки «Начать перевозку».
E3. Карточка заказа показывает маршрут, груз/тип кузова, цену, статус русским словом.

F. ЧАТ (должен быть лучше WhatsApp)
F1. Отправка текста — пузырь появляется, на сервере сохраняется.
F2. Персистентность: написать → `stopApp` → перезапуск → вернуться в ту же комнату →
    СООБЩЕНИЕ НА МЕСТЕ (значит дошло до сервера, а не только optimistic).
F3. Офлайн: выключить сеть → отправить → должен быть статус «в очереди / отправим
    позже», НЕ потеря; включить сеть → дослалось без дубля.
F4. Имена собеседников реальные, не «Собеседник».

G. УВЕДОМЛЕНИЯ
G1. Время показывается по-человечески (локализованное), не сырой UTC «2026-06-...T..».
G2. Тап по уведомлению не крашит; ведёт на нужный экран.
G3. (если соберёшь standalone) Push о сообщении, когда ЭТА комната открыта, НЕ
    показывает баннер; на другом экране — показывает. Иначе — manual по
    `qa/PUSH_MANUAL_TEST_PLAN.md`.

H. СТАТУСЫ И ЯЗЫК
H1. Нигде нет сырых «ACCEPTED»/«None»/«undefined»/ключей вида `status_xxx`. Статусы —
    Ожидает/Принят/В работе/Завершён/Отменён/Отклонён/Истёк.
H2. Смена языка RU↔EN↔KK↔ZH на лету (`feed-lang-switch` / в профиле): тексты и
    статусы меняются без перезапуска; нет «вылезшего» текста за кнопки (overflow) на
    KK/RU.

I. ПРОФИЛЬ/ВЕРИФИКАЦИЯ
I1. Профиль после входа НЕ пустой (имя/город есть, не «Добавить имя» если данные есть).
I2. Personal photo: основное действие открывает КАМЕРУ (не галерею); галерея —
    вторичная ссылка. (на симуляторе камера ограничена — проверь хотя бы что тап
    открывает камеру, не сразу галерею).

J. «МЁРТВЫЕ» КНОПКИ (сквозная проверка)
J1. Пройди по всем экранам обеих ролей и убедись: каждая видимая кнопка что-то делает
    (навигация/действие/тост), нет кнопок, ведущих в никуда или на чужой экран.
