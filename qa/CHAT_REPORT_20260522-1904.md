## 3. Backend blockers (требует backend изменений)

Из предыдущей сессии остаются:

### BL-1 — `user.get('full_name', 'Водитель')` antipattern
`backend/api/marketplace.py:686, 716` и в accept/reject/counter (~lines 1049-1131). `dict.get(key, default)` возвращает None если значение None. Frontend hack (`cleanNotifText` в NotificationsScreen) скрывает на дисплее, но backend пишет «None предлагает» в БД и push body. Real fix:
```python
text = f"{user.get('full_name') or 'Водитель'} предлагает ..."
```

### BL-2 — `$` hardcoded в push/notification text
`backend/api/marketplace.py:685-686`:
```python
title = f"💰 Новое предложение ${body.amount}"
text = f"... предлагает ${body.amount} за {from_city}→{to_city}"
```
Cargo в KZT/RUB/CNY получает push с `$`. Backend должен подгружать currency и подставлять символ (`₸`/`₽`/`¥`/`$`).

### BL-3 — chat_rooms data investigation
Frontend код корректен (полю audit'нул в этой сессии). Если на проде у user'a НЕТ rooms между ним и driver'ами/шипперами после ставок — нужна prod SQL проверка:
```sql
SELECT id, participant_1, participant_2, cargo_id, trip_id, last_at
FROM chat_rooms
WHERE participant_1 = '<user_id>' OR participant_2 = '<user_id>';
```
+ `pm2 logs` для exception от `_ensure_chat_room_inline` (см. PR-B marketplace.py:704).

### BL-4 (новый) — Suppression push при просмотре чата
Когда юзер в открытом ChatScreen и приходит push для этого же room — push должен не показывать banner (как WhatsApp). Сейчас Notifications в foreground всегда показывают banner (через `setNotificationHandler {shouldShowAlert: true}`). Чтобы фильтровать по active room_id нужен либо:
- глобальный store (Zustand/Context) с активным room_id, и handleNotification который проверяет `data.room_id !== currentRoomId`
- либо backend в push payload не отправляет если sender видит что receiver в комнате (требует presence)

Out of scope этой сессии — пользователь это редко замечает; на TestFlight 14 не блокер.
