## B. РЕАЛИЗОВАТЬ: переделка фото-документов верификации (решение владельца)
Сейчас: Гражданство → Identity (личное фото + удостоверение 2 стороны + ФИО/ИИН/
дата) → VehicleDocs (техпаспорт 1 фото + права 1 фото + СЕЛФИ с правами) →
Параметры → submit.

**Целевой флоу (сделать так):**
- **Личное фото / селфи с правами — УБРАТЬ полностью** (и с Identity, и из VehicleDocs).
- В начале документа личности — **выбор типа: удостоверение ИЛИ паспорт**.
- **Три документа, у КАЖДОГО 2 стороны (лицевая + оборотная):**
  1. Удостоверение/паспорт — 2 стороны
  2. Техпаспорт (СРТС) — 2 стороны
  3. Права (ВУ) — 2 стороны
- Порядок шагов: **Гражданство → Документ личности (2 стороны) → Техпаспорт
  (2 стороны) → Права (2 стороны) → Параметры фуры → submit.** Прогресс-бар
  обновить под новое число шагов.

**Что потребуется (ориентир, проверь по факту):**
- Frontend: `IdentityStepScreen.js` — убрать личное фото, добавить тумблер
  удостоверение/паспорт; удостоверение/паспорт остаются 2 стороны (паттерн
  `pickIdSide` уже есть). `VehicleDocsScreen.js` — убрать селфи с правами;
  техпаспорт и права сделать по 2 стороны (front/back), как удостоверение.
  Возможно вынести техпаспорт и права в отдельные шаги (или один экран с двумя
  парами слотов) — по образцу существующих слотов.
- Backend `backend/api/registration.py` — добавить недостающие эндпоинты
  оборотных сторон: `documents/tech-passport-front|back`,
  `documents/license-front|back`, для паспорта `documents/passport-front|back`
  (сейчас есть только `id-front/id-back`, одиночные `license`, `passport`,
  `tech`). Добавить колонки `has_*_back`/`*_back_url` в схему регистрации и
  вернуть их в `get_status` (для повторного входа — подтягивать уже
  загруженные стороны, как сделано для `has_id_front/has_id_back`).
- i18n: новые ключи по 4 языкам (RU/KK/ZH/EN симметрично, иначе падает
  `npm run qa:i18n`): подписи сторон техпаспорта/прав, тумблер
  удостоверение/паспорт.
- Обязательно: `npm run qa:i18n` зелёный + `npm run build:web` → «Exported: dist».
- **Это Graphify-gated зона** (backend registration + navigation). Держи флоу
  рабочим на каждом шаге, submit не должен 500-ить при пустых OCR-полях.

**Maestro:** `verify-3docs-2sides.yaml` — Гражданство → выбор удостоверение →
2 фото → техпаспорт 2 фото → права 2 фото → Параметры → submit; проверить, что
селфи/личного фото НЕТ и «Шаг N из N» корректный. + `verify-reentry-prefill.yaml`
(повторный вход подтягивает загруженные стороны).
