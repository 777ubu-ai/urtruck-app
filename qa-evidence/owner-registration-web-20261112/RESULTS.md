Фактический исходный HEAD продолжения был `6b0f49c1da70c2697b9c889b2bd9bf8412608572`, ветка та же; предыдущий commit `841660af...` оставался предком, отката не было. Регистрацию и публичную store landing не меняли.

Изменение клиентского файлового пути: `DealWorkspaceScreenV2` и `DealAttachments` открывают PDF, XLS/XLSX/CSV и прикреплённые фото по `roomId` + `attachmentId` через `chatAPI.getPrivateFile`, затем проверяют MIME/размер и открывают содержимое из приватного cache через системный viewer. Удалён `Linking.openURL` fallback на выданный подписанный URL на этих двух текущих экранах. Голосовые и чат-фото уже используют тот же авторизованный API и scope аккаунт/комната/message. Добавлены unit/contract/runtime-тесты; прежние контрактные проверки обновлены под защищённый путь. Не менялись backend, серверное хранилище, аккаунты или production-ссылки.

Новые проверки исключают прямой signed-URL fallback в активных клиентских экранах и подтверждают обработку отказа auth/MIME/размера на тестовом seam. В актуальном коде генератор подписанных ссылок имеет ограниченный TTL (обычно 86400 секунд); механизм немедленного отзыва уже выданных внешних/Supabase ссылок не подтверждён. Production-ключи и ссылки не трогались. Следовательно файловый P1 остаётся OPEN до trusted QA2/storage-проверки, решения по legacy URL и независимого review.
