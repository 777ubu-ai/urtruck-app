## Модель доступа в кандидате

- Для вложения сделки сервер требует авторизованного пользователя, существующую комнату, участие пользователя, разрешённое состояние сделки и точную связь `attachment_id → conversation_id`. Проверяются запись загрузки, отправитель/участник, сообщение и допустимая цель хранения. Сервер читает байты сам, повторно проверяет связь после чтения и отвечает `private, no-store`/`nosniff`.
- Для фото и голосового сервер требует участника конкретной комнаты, принятую сделку и связь `message_id → room_id`; после чтения связь проверяется повторно. Ответ не кэшируется.
- Клиентские защищённые пути находятся в `src/utils/privateFileTransport.js`; экранов чата/PDF вызывают их через `src/screens/DealWorkspaceScreenV2.js` и `src/components/deal/DealAttachments.js`.
- Основная реализация: `backend/api/deal_room.py` (`GET /api/v1/chat/conversations/{conversation_id}/attachments/{attachment_id}/content`) и `backend/api/chat.py` (`GET /api/v1/chat/messages/{room_id}/media/{message_id}`).
