# Диагностика застоя счётчика внешней ленты — 27.10.2026

## Что подтверждено

- По присланным снимкам счётчик ленты грузов: 3 498 и 3 536. На последнем снимке для превышения 10 000 нужно ещё как минимум 6 465 актуальных карточек.
- Последний доступный QA2-аудит от 26.10.2026 08:11 UTC зафиксировал 6 225 переданных в API карточек за день, из них 5 942 остались на ручной проверке. Это объясняет низкий прирост активного счётчика: частота опроса в 2 секунды обновляет выдачу, но не превращает записи review в активные.
- Тот же аудит сообщает режим `EXTERNAL_FREIGHT_SOURCE_MODE=incoming`, тогда как целевая цепочка — источники → `@UrTruck_UT` → разбор публикаций канала → API. Это расхождение требует проверки и переключения только по штатному QA2-процессу.
- Публичный QA2 endpoint версии отвечает `1.0.50` (сборка `2026-10-26 15:44`). Endpoint счётчика API возвращает HTTP 401 без пользовательского токена, поэтому актуальные раздельные значения cargo/vehicle и причины очереди сейчас не считаны.
- SSH с текущей Mac-сессии на `qa2.urtruck.kz` отклонён `Permission denied (publickey)`. Инструмент удалённого рабочего стола сообщил об исчерпании месячной квоты вызовов. Состояние сервисов, очередь и БД с сервера не менялись.
- Исправлен локальный виджет счётчика `ExternalFreightEntry`: опрос раз в 2 секунды вместо 60, без параллельных запросов; при единичной ошибке остаётся последнее успешное значение. Изменение не создаёт карточки и не активирует ручную очередь.

## Вывод и блокер

Основное измеренное узкое место — большая доля отправленных записей уходит в ручную проверку, а не в активную выдачу. Более частый опрос счётчика чинит только своевременность/устойчивость бейджа и сам по себе не добавляет активные карточки. Без доступа к актуальной QA2 БД нельзя честно выбрать и перепроиграть записи, подтвердить точную причину каждой категории или гарантировать превышение 10 000 карточек. Массовая активация неоднозначных объявлений нарушила бы требование оставлять неоднозначное направление/тип на проверке и не создавать фиктивные карточки.

## Следующий необходимый доступ

Нужен один из вариантов доступа к QA2: рабочий SSH-ключ с разрешением чтения состояния/резервной копии и штатного ограниченного rollout, либо доступный Desktop Commander бюджет; также нужна авторизация приложения для чтения раздельных счётчиков. Изменение бейджа локальное, не развёрнуто. Production не затрагивался. Деплой и изменение очереди не выполнялись. Автотесты изменения бейджа не запускались.
